# 1.1.5 同版本更新：页面能力识别、极简直传与文件夹批处理

更新时间：2026-08-24

状态：源码修复、隔离验证和 Windows 一键安装包重建完成；版本仍为 `1.1.5`，未提交、未安装。

## 问题现象

- 专属 Chrome 已登录且肉眼可见输入框，但软件可能连接到另一个历史标签页，随后误报没有输入框或没有模型选择器。
- Plus/Pro 的新版三级模型菜单可以手动使用，自动化却可能只返回“跟随当前模型”；免费版没有传统模型菜单时又会被误报为页面异常。
- 主窗口 renderer 加载或退出时只有黑色背景，用户无法区分资源加载失败、renderer 崩溃和 GPU 问题。
- 批量任务希望完全沿用网页当前模型和思考设置，避免每张任务都探测、打开或切换模型菜单。
- “批量降 AI 感”只能处理当前项目归档，不能选择任意本地图片文件夹。

## 真实根因与证据

1. 专属 Chrome 的目标页选择主要依赖 URL。首页、历史对话和多个标签页同时存在时，URL 分数不能证明哪个页面拥有当前可用输入框。
2. 输入框可用性和模型菜单可用性曾在模型刷新流程中形成隐式耦合。免费版的自动模型页面没有传统选择器，但这不代表页面未准备好。
3. 主窗口缺少 `did-fail-load`、`render-process-gone` 和 `child-process-gone` 的本地诊断与可见失败页；黑屏截图本身不足以证明 GPU 是根因。
4. 正式日志证明三路的配置、上传和发送已经串行，结果等待并行；主要浪费来自同配置页面的重复确认，不是缺少更多并发框架。
5. 外部文件夹不能直接把任意路径交给 renderer。需要主进程持有真实路径并用短期会话限制后续处理范围。

脱敏日志中的三路提交时间线为：任务 1 配置/上传/发送 `16:32:57/16:33:06/16:33:18`，任务 2 为 `16:33:27/16:33:37/16:33:48`，任务 3 为 `16:33:58/16:34:07/16:34:19`；结果在 `16:35:04`、`16:35:24`、`16:35:55` 分别保存。没有输出提示词、图片、Cookie、Token 或登录资料。

## 解决方式

### 页面能力与目标页

- 目标页选择综合 URL、可见状态、可用输入框和页面正文；活动输入框页面优先于无输入框的历史标签页。
- 任务获得页面后继续锁定同一 target，不在执行中因另一个标签页导航而漂移。
- 输入框检测与模型菜单检测分离。输入框已可用但没有模型选择器时，返回 `modelMode: automatic` 和成功状态；Plus/Pro 仍使用现有三级菜单读取与确认。
- 删除不受支持的 `--disable-blink-features=AutomationControlled` 参数，不尝试使用反检测补丁绕过平台保护。

### 极简直传

- 新增“极简直传”模式，沿用网页当前模型与思考设置。
- 正式做图在该模式下模型 DOM 查询、模型点击、思考强度查询和思考强度点击均为 `0`；日志只记录“沿用网页当前设置（未探测）”。
- 模式仍保留页面可用、附件预览、发送建立、结果识别和保存门禁；不确定消息是否已经发送时仍禁止补点。
- AI 分析和网感姿势原本不执行正式做图的模型选择流程，因此同样沿用当前网页设置，并继续共享页面操作互斥和访问保护门禁。

### Electron 黑屏诊断

- 主窗口先隐藏，`ready-to-show` 后再显示，避免 renderer 尚未绘制时先暴露空黑背景。
- 将主 frame 加载失败、renderer 退出和子进程退出写入本地 `logs/electron-runtime.ndjson`。
- 首次 renderer 异常只重载一次；仍失败时显示不依赖远程资源的本地诊断页，不再无限黑屏。
- 没有证据证明 GPU 是本轮共同根因，因此没有全局关闭 GPU；保留既有、范围最窄的 Windows GPU sandbox 兼容开关。

### 任意文件夹批量降 AI 感

- 金色弹窗增加“结果归档 / 导入文件夹”来源切换，空项目也可进入文件夹模式。
- 主进程扫描 JPG、JPEG、PNG、WebP 和 HEIC；HEIC 只有经过 `sharp` 真实 HEIF 解码后才可选，损坏或不可解码文件显示为单张错误。
- 支持缩略图、文件名、尺寸、逐张勾选、全选、清空、顺序处理、实时状态和停止。
- renderer 只接收会话 ID 和条目 ID；真实源路径留在主进程。处理前再次校验文件仍在所选目录、大小合法且不是目录逃逸。
- 每张图使用独立随机种子，保持原宽高，不覆盖原图；结果写入源目录下新的 `耀创工坊_降AI感_日期时间` 子目录，外部图片不写入项目结果归档。
- 单张失败只标记当前条目，继续处理其余选择；停止会在当前图片完成后终止领取下一张。

## 开源库取舍

- 继续使用已安装的 `playwright-core` 作为页面操作层、`chrome-remote-interface` 作为底层 CDP transport 和诊断层。
- 本轮没有新增 XState：现有保护状态、任务记录和批次调度已经是明确状态模型，引入第二个状态机只会制造双重真相源。
- 本轮没有新增 p-queue：`ChatGptControlQueue` 已提供页面操作互斥、同操作 single-flight 和独占任务槽。
- 本轮没有新增 Cockatiel：现有访问保护策略已经实现固定冷却、一次恢复检查、单路到多路恢复和有限重试分类。
- 本轮没有新增 Zod：当前断点和运行记录已有集中规范化函数，本次没有引入新持久格式；若以后重做外部导入协议，再单独评估运行时 schema。
- 不接入 Stagehand、Crawlee、Patchright、Camoufox、rebrowser-patches、rrweb 或完整 OpenTelemetry，避免真实登录资料、隐私和重复调度风险。

## 验证边界与残余风险

- 本轮没有通过真实账号连续发送来制造访问保护，也没有操作正式 Chrome 登录资料；页面夹具和隔离 Electron 验证不能冒充真实付费账号端到端验证。
- 免费版自动模型页面现在不会被误报为异常，但网页没有公开具体模型名称时，软件也不会伪造模型名称。
- 客户电脑的历史黑屏没有对应 `electron-runtime.ndjson`，因此只能确认新的诊断与恢复路径有效，不能追溯断言旧现场一定由 GPU 或资源加载导致。
- ChatGPT 网页 DOM 仍可能继续变化；目标页选择和能力识别降低了脆弱性，但不能保证第三方网页永不改版。

## 经验教训

- 页面“有没有输入框”和“有没有模型菜单”是两个独立能力，不能用一个控件推断另一个控件。
- 减少网页操作的最佳方式是允许显式沿用当前配置，而不是给重复点击增加更多固定延时。
- 平台保护只能安全暂停和受控恢复，不能通过反检测参数或密集探测绕过。
- 外部文件批处理必须把真实路径和授权范围留在主进程，renderer 只使用短期会话标识。
- 成熟库只有在承担唯一职责时才有价值；已有实现覆盖同一职责时，克制新增依赖比“吸收项目”更稳定。
