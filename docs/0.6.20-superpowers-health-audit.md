## 问题一：撤销素材或修改来源后仍可发送旧提示词

### 现象

- 带穿搭参考图和网感姿势生成提示词后，删除全部穿搭参考图或清空姿势，发送检查仍显示可开始。
- 修改区域提示词实际使用的原图理解字段，或切换人脸主参考图后，旧提示词仍可发送。

### 根因与证据

- 穿搭和姿势签名只在当前仍存在相应素材时才校验，删除或清空后对应检查项直接消失。
- 发送门禁只验证提示词非空和两种局部签名，没有验证区域提示词正文是否仍由当前项目来源生成。
- 最小复现中 `wardrobeRemoved`、`poseCleared` 和 `bothRemoved` 均返回零阻断项；修改场景、光影或人脸主参考图后，`PromptBuilder` 重建文本已经变化，但发送检查仍返回零阻断项。

### 解决方式

- 区域模式始终比较穿搭签名和姿势签名，包括空集合与未选姿势状态。
- 姿势未选择时同时确认旧草稿不残留 `【姿势规则】`。
- 增加纯文本 `prompt-source` 新鲜度检查，比较当前区域草稿与现有 `regionalPrompt(project)` 的重建结果。
- 自定义提示词模式不参与该比较；穿搭分支未使用的场景变化不会被误阻断。

## 问题二：替换主图后残留旧主图派生状态

### 现象

- 替换主图时，红圈、蒙脸和网感姿势会清空，但旧主图的场景、姿态、面部朝向、光影分析、自定义保护项和当前提示词仍保留。

### 根因与证据

- `setMainImage` 只重置了画布标记与姿势状态，没有把原图分析和提示词视为主图派生数据。
- 真实 Store 状态迁移复现确认：主图名称已变化，而四项旧分析和旧草稿仍原样存在。

### 解决方式

- 更换主图时同时清空四项原图分析、自定义保护项和当前提示词草稿。
- 人脸参考图、穿搭参考图、提示词历史、发送历史、结果归档和项目数据仍保留。

## 问题三：重启后已发送快照复活为当前草稿

### 现象

- 当前草稿被明确清空但提示词历史仍存在时，自动保存后重启会把最近一次已发送快照恢复为可编辑、可再次发送的当前草稿。

### 根因与证据

- `normalizeProjectState` 在缺少 `promptDraft` 时无条件回退到 `promptHistory[0]`，并把 `usedForSend` 强制改为 `false`。
- 最小恢复实验确认 `usedForSend: true` 的历史快照被恢复为当前草稿。

### 解决方式

- 不再把 `usedForSend: true` 的发送快照恢复为当前草稿；显式草稿自身为已发送状态，或与历史中同 ID 的已发送快照匹配时，同样拒绝恢复。历史条目本身保持不变。
- 对没有 `usedForSend` 标记的旧项目历史继续保留原有兼容恢复行为。

## 问题四：更换主图后迟到的旧分析重新污染项目

### 现象

- AI 原图分析或网感姿势分析仍在等待时更换主图，旧请求完成后会把旧图分析或姿势建议写回新项目。

### 根因与证据

- 两条异步流程在请求完成后直接 `updateProject`，没有核对当前主图是否仍是发起请求时的图片。
- 独立代码复审指出该时序后，Store 级延迟写回测试稳定复现旧主图结果可覆盖新项目。

### 解决方式

- 增加一个 Store 级原子写回动作，只有请求主图 ID 与当前主图 ID 一致时才接受分析补丁。
- AI 原图分析和网感姿势分析均使用同一门禁；旧结果被拒绝时显示“原图已更换，本次旧图结果已忽略”。

## 经验教训

- 提示词有效性必须覆盖素材的增加、替换、删除和清空，不能只在当前素材存在时检查。
- 新鲜度应按当前互斥分支真正使用的来源判断，避免遗漏，也避免无关字段变化造成误阻断。
- 更换根素材时应同步清理它的派生状态，但保留历史事实和用户独立素材。
- 发送快照是历史事实，不是可继续编辑的草稿；恢复兼容必须保留两者边界。
