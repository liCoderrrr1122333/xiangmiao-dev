# 耀创工坊 1.2.4 API 上游拒绝热修

日期：2026-08-26  
版本：保持 `1.2.4`，已重新打包，未安装、未提交

## 问题现象

香蕉生图三张批次在任务 1 停止，界面显示“上游连续两次拒绝请求，已暂时停用 120 秒”，最终保存 `0/3`，其余两张保持待执行。

## 真实根因与证据

- 脱敏运行日志显示任务 1 已正常进入 API 通道，约 19 秒后以 `CIRCUIT_OPEN` 结束；关闭 TUN 后的既有直连检查也已证明 DNS、TLS 和 API 路由可达。因此这次不是“访问不到中转站”，而是请求到达后被香蕉上游明确拒绝。
- 客户端旧策略收到第一次 HTTP 406 后等待 3 秒，自动重复同一个付费生成 POST；第二次仍为 406 才打开熔断，所以错误文字写成“连续两次”。这会产生无收益的重复请求，也覆盖了首个服务端原因。
- 现场日志只保存包装后的熔断文案，没有记录模型、分辨率、附件总字节数及服务端脱敏错误字段，无法继续区分模型分组、上游路由或请求内容限制。

## 解决方式

- 标准图片和香蕉生图收到首个明确 HTTP 406 后立即停止，不再自动重复付费生成请求。
- 当前模型立即进入 120 秒短时熔断；熔断期间再次点击只在本地返回暂停状态，不发送付费 POST。熔断到期后只允许用户新发起的一次请求，不在内部循环重试。
- 解析并脱敏保留服务端 `message`、`type`、`code` 和允许公开的请求 ID；错误信息与日志继续清除 API Key。
- 任务日志增加模型、分辨率、附件数量和附件总字节数，不记录提示词正文、图片内容、Cookie、Token 或 Key。
- 失败任务和未启动任务继续保存在原子事务断点；批次状态明确提示稍后重试或手动改用标准图片，且不会静默切换模型。
- 修正熔断文案为“刚刚被上游拒绝”，不再把一次 406 误报成连续两次。

## 经验教训与边界

- 付费生成的 HTTP 406 是明确拒绝，不是安全可重试的网络瞬态错误；客户端不能用自动重复提交掩盖它。
- 短时熔断能防止重复扣费和错误风暴，但不能让服务商上游从 406 自动恢复。若脱敏详情仍显示模型路由或分组拒绝，需要服务商修复对应上游，或由用户明确改用标准图片模型。
- 在没有官方接口文档、服务端任务 ID 和幂等键的情况下，不猜测另一套付费端点，也不静默替换用户选择的模型。
