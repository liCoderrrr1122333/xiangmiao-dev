# 耀创工坊 0.6.22 可选蒙脸更新

日期：2026-08-14

## 问题现象

- 用户已上传原图、画好红圈并生成提示词后，如果没有再执行“一键蒙脸”，工作台仍会阻止做图。
- 部分素材在保留红圈定位、不覆盖圈内人脸时融图更自然，但旧流程无法选择这条路径。

## 根因

1. 渲染层检查表把一键蒙脸定义为 `required` 和 `block`。
2. `App.tsx` 发送入口又单独校验 `faceOcclusionEnabled` 和遮挡格栅。
3. 主进程 `send:create-package` IPC 还有一道蒙脸硬门禁，形成多层重复阻断。
4. 现有 `renderRedCircleImage` 本已支持无遮挡格栅时只画红圈，无需重写附件系统。

## 解决方式

- 红圈仍然是正式做图的必填条件；“一键蒙脸”改为可选建议项，未启用时不再阻止发送。
- 未蒙脸时生成并上传 `01_红圈主垫图.png`；启用蒙脸时继续上传 `01_红圈蒙脸主垫图.png`。
- 未标注原图仍只作为 `00_仅本地原图备份`，不进入 ChatGPT/Gemini 自动化上传数组。
- 提示词使用通用“红圈主垫图”职责描述，操作指南则根据实际选择写入对应文件名。
- 人脸参考图、穿搭参考图、网感姿势、提示词快照、Provider 自动化、并行调度和结果保存逻辑未改动。

## 经验教训

- 可选视觉预处理不应在检查表、渲染发送入口和主进程 IPC 中各有一道硬门禁；三层规则必须一致。
- 放开蒙脸不等于放开原图上传。正式附件始终是红圈主垫图，未标注原图仍只能本地备份。
- 现有底层渲染函数已支持目标状态时，应优先移除错误的业务门禁，不重写附件系统。
