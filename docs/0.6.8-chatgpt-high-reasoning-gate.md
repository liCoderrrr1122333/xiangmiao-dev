# 0.6.8 ChatGPT 高思考强度门禁

日期：2026-08-10

## 功能范围

- GPT-5.5 和全部 GPT-5.6 分支在原图分析或图片生成前，自动确认 ChatGPT 当前思考强度为“高”。
- 继续保留现有模型选择、跟随当前模型、附件上传、提示词发送、1/2/3 路并行、结果保存和断点续做流程。
- 不把该策略应用到 Gemini、o3 或其他未明确要求的模型，不改变项目格式、画布、图像尺寸、红圈保护、一键蒙脸、参考图、提示词快照和用户设置。

## 现象

- ChatGPT 已正确切换到 GPT-5.5 或 GPT-5.6 时，输入区的思考强度滑杆仍可能停留在“标准”或其他档位。
- 原自动化只把“模型名称正确”作为上传前门禁，没有检查同一输入区的思考强度。
- 因此程序可能在模型正确但强度不是“高”的情况下继续上传图片和发送提示词，做图质量缺少一致保障。

## 根因

- 模型菜单和思考强度属于 ChatGPT 输入区的两个独立状态，旧逻辑只确认模型状态。
- 原页面夹具初始就是“高”，无法暴露“模型正确但强度仍为标准”的缺口。
- “跟随当前模型”分支在读取当前模型后直接返回，没有统一进入强度确认门禁。
- ChatGPT 的“高级”菜单分支、模型标签和“高/极高”强度文字需要严格区分，不能仅用模糊的“高”字匹配。

## 解决方式

- 在 `chatGptModelPolicy` 中新增独立思考强度策略，精确分类 `low / medium / high / extreme / unknown`。
- `shouldForceChatGptHighReasoning` 只对 GPT-5.5 和 GPT-5.6 系列启用；`GPT-5.6 Sol / Terra / Luna` 均纳入，o3 和 GPT-5.3 等不受影响。
- 新增 `chatGptReasoningControl`，先定位真实输入区模型/强度入口，再用 CDP 可信鼠标和键盘事件操作滑杆。
- 滑杆使用 `Home` 回到起点后逐级 `ArrowRight`，每一步重新读取页面状态；只在精确识别为“高”时停止，不会把“极高”或“高级”误当成目标。
- 关闭菜单后再次确认“高”仍然保留；找不到滑杆、无法操作或无法确认时立即失败。
- 显式模型和“跟随当前模型”统一调用同一个高档门禁；原图 AI 分析与图片生成均在附件上传前执行。
- 门禁失败时本轮在上传和发送前停止，显示可读状态并写入脱敏诊断，不静默继续做图。

## 测试改进

- 页面夹具初始强度由“高”改为“标准”，并加入真实 range 状态和 `input/change` 更新逻辑。
- 夹具使用生产 `ensureChatGptHighReasoning` 模块验证 GPT-5.6 Sol 和 GPT-5.5 均从标准移动到高。
- 增加 20 轮菜单循环，确认最终保持 GPT-5.5 高档且没有菜单残留。
- 增加真实账号只读脚本 `verify:chatgpt-reasoning-live`，不上传附件、不写入提示词、不发送消息。

## 经验教训

- 模型确认和思考强度确认必须是两个独立门禁，不能从模型名称推断强度状态。
- 自动化测试必须从错误状态开始；夹具默认已经正确会掩盖最关键的修复路径。
- “高”和“极高”、“高级”菜单文字不能模糊匹配，目标状态必须精确分类并在菜单关闭后复核。
- 网页滑杆应优先使用可信 CDP 输入，并在每一步后读取真实页面状态，不能只设置 DOM 属性后假定成功。
- 高质量偏好属于发送前条件；无法确认时应在附件上传前停止，不能用未知状态继续消耗任务。
- 使用真实应用数据做 UI 回归会触发既有自动保存水合与版本迁移。后续只需验证网页状态时，应优先使用直接 CDP 脚本；必须启动完整应用时，应事先记录指纹并逐字段对账。

## 残余风险

- ChatGPT 页面 DOM、滑杆语义或键盘行为仍可能更新；当前策略会明确失败并阻止发送，而不是静默使用未知强度。
- 不同账号可能出现不同 GPT-5.6 分支或本地化文字；策略已覆盖当前真实账号和中英文强度标签，但新页面结构仍需重新实测。
