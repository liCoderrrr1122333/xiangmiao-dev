# 人脸参考图发型优先级与提示词去重

日期：2026-08-14

状态：已随 `0.6.17` 正式发布，安装包与完整回归结果见 `docs/0.6.17-web-pose-and-hairstyle-priority.md`。

## 问题现象

- 现有提示词把人脸参考图多次限定为“只负责身份”或“只负责身份与五官”，没有把发型作为明确职责。
- 主提示词、穿搭最高优先级段、负面提示词、操作说明和结果修正提示词多次要求红圈外头发或发丝保持原图。
- 单纯在末尾追加“发型以主参考图为准”仍会被前面重复出现的旧保护规则抵消，尤其是穿搭段位于人脸基础提示词之前，权重更高。

## 根因

- 早期工作流将红圈视为唯一编辑区域，头发被归入红圈外保护对象；后来加入穿搭授权区域时，只为衣物配饰增加例外，没有同步扩大发型授权边界。
- 同一保护语义分别维护在 `PromptBuilder`、`wardrobePrompt`、`templates`、`operationGuideBuilder` 和 `revisionTemplates`，逐步产生重复和不一致。
- 导出的 `Negative Prompt` 和二次修正提示词仍保留旧规则，即使一键生成正文更新，后续流程仍可能把发型恢复成原图。

## 解决方式

- 使用 Hale 确认的两段原文作为唯一发型基准：人脸参考图负责身份与发型，人物身份综合全部人脸参考图，发型以主参考图为唯一基准。
- 完整保留发型优先级要求：允许为匹配主参考图重建目标人物头发，同时保持原图头部角度、大小、面部朝向、姿态和遮挡关系。
- 将授权边界统一为“人脸、必要头发区域、明确指定的衣物配饰区域可编辑；其他内容保持原图”，不再重复使用“红圈外头发保持不变”。
- 穿搭段只说明素材不得串用和穿搭执行要求，不再重复覆盖人脸与发型职责。
- 同步修正一键生成正文、检查清单、发送说明、操作指南、导出负面提示词和结果修正提示词，避免后续阶段重新引入旧发型锁。
- 默认保护项中移除“不改变红圈外头发”和“不改变发丝边缘”；兼容过滤器继续识别老项目中的这两项旧值，但不会将其写入新提示词。
- 未修改 ChatGPT/Gemini Provider、附件上传、模型选择、并行调度、结果保存、项目格式或用户数据。

## 验证结果

- 新增回归覆盖单张/多张人脸参考图、主参考图优先、穿搭参考图并存、正文、检查清单、Negative Prompt、发送说明、操作指南和结果修正提示词。
- 修复前测试稳定显示穿搭最高优先级段仍包含“不得重绘头发”，且人脸参考图只负责身份与五官。
- 修复后确认用户核准的两段发型规则存在，旧冲突句不再进入任何生产提示词。
- `npm run typecheck`：通过。
- `npm test`：`151/151` 通过。
- `npm run verify:ui`：通过，14 张工作台深浅主题和多尺寸截图正常。
- 本轮没有启动真实 ChatGPT/Gemini 生成，也没有发送用户图片；验证范围是本地提示词生成、源码回归和 Electron 工作台 UI。

## 经验教训

- 新的授权例外不能只附加在提示词末尾，必须替换所有更高优先级或后续阶段中的冲突旧规则。
- 正文、负面词、操作说明和修正提示词属于同一语义链，任何一处沿用旧边界都可能在真实生成中抵消新要求。
- 去重不等于删除所有提醒。素材职责保留一次详细定义，最终检查只做简短复核，避免使用不同措辞重复扩展同一规则。
