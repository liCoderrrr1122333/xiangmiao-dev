# 耀创工坊 1.1.2 机器人图标更新

更新时间：2026-08-17

## 现象与需求

- Hale 指定新的机器人头像作为耀创工坊统一图标，要求任务结束后生成最新一键安装包并放到桌面。
- 旧图标链仍使用紫黑镜头吉祥物，与本次确认的品牌画面不一致。
- 首版机器人图标忠实保留了原图的整块浅色背景，Windows 缩略后形成明显白色方块，红环和机器人主体显得偏小；Hale 要求红环直接成为外边界，整体占比接近微信开发者工具图标。

## 根因

- 应用图标、安装器、快捷方式、托盘、favicon 和工作台左上角来自多份不同尺寸资源；只替换其中一张 PNG 会造成新旧图标混用。
- Windows 桌面还依赖多尺寸 ICO，直接把大图当作单尺寸图标会让 16/24/32px 显示质量下降。

## 解决方式

- 以 Hale 提供的 `1254x1254` 机器人 PNG 为唯一视觉源，保持机器人、红色环线、颜色、光影和内部细节不变。
- 生成式去背预览会把透明区域画成棋盘格并轻微改变主体，因此没有用于正式资源；正式图标采用原始像素确定性处理，只删除与画布边缘连通的浅色背景。
- 将红环和机器人组合等比放大，使可见内容在 `1254x1254` 画布中占 `1170x1166`，四周保留少量透明安全边距，不裁切红环、机器人或平板。
- 同步替换 `build/yaochuang-mascot-source.png`、`public/yaochuang-unified-v2.png` 和 `public/yaochuang-tray.png`。
- 从同一主图生成 16、24、32、48、64、128、256 七档 ICO，并保证 `build/icon.ico`、`build/yaochuang-unified-v2.ico`、`public/yaochuang.ico` 字节一致。
- 安装身份、版本号、应用目录、用户数据目录和自动化逻辑均保持不变。

## 经验教训与残余风险

- 图标更新必须从唯一主图同步生成整个资源链，不能逐文件手工替换。
- 大图确认后仍要检查 16 至 96px 的实际缩略效果，并反向提取安装器和 EXE 图标，避免打包器继续引用旧资源。
- 图标去背必须核验真实 alpha 通道；视觉上的棋盘格图片仍可能是全不透明 RGB，不能作为透明图标交付。
- 对桌面图标大小的判断应同时比较 32px 实际渲染和 alpha 可见边界，不能只看 1254px 主图。
- Windows 可能短时间显示旧快捷方式图标缓存；安装新包或重新创建快捷方式后会读取新 ICO。
