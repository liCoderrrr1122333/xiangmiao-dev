# 耀创工坊 AI 分析与网感姿势发送热修

更新时间：2026-08-22

状态：版本仍为 `1.1.2`；本轮 AI 分析、网感姿势与访问保护协同修复已随最新安装器完成同版本覆盖安装，未提交代码，也未自动执行真实账号付费请求。

## 问题现象

- AI 分析偶发提示发送未被 ChatGPT 确认，输入框文字和附件仍保留。
- 网感姿势偶发同样无法发送；再次点击后会被五分钟发送安全等待阻塞。
- 另一次网感姿势消息已发送并收到助手回复，但等待四分钟后仍提示没有完整返回 8 条姿势。

## 现场证据与根因

1. 正式脱敏日志显示，失败前附件门禁为 `ready=true`、附件数为 1、发送按钮可用；失败后输入框仍有完整文字，用户消息数和消息节点数均未增加，页面没有生成状态。根因是后台可信点击偶发被网页吞掉，但旧实现只判断“点击调用成功”，没有确认该点击真正产生发送。
2. 旧实现把上述明确未发送状态也记为“不确定发送”，写入五分钟全局安全锁；AI 分析还会把空白会话保存为待恢复记录。这解释了重试时长时间等待。
3. 网感姿势指令同时要求“不要英文”和返回英文固定 JSON 键 `poses/id/title/description`，规则互相冲突。现场失败回复只有 67 个字符且不是 JSON，回复提取器正确抓到了助手正文，失败发生在内容格式而非 DOM 选错。
4. 当结构化回复已经结束但格式不合格时，旧等待器仍会耗尽 240 秒总时限，导致明确失败暴露过慢。

## 解决方式

- AI 分析和网感姿势在首次点击后先观察 8 秒；只有输入和附件仍完整、消息计数完全未变、页面未跳转、没有生成状态且没有访问保护时，才使用 DOM 方式补点一次。
- 任何用户消息、消息节点、页面跳转、生成状态或访问保护信号都会禁止补点，避免重复请求。
- 两次点击都被确认无效时，不再写入五分钟安全锁；AI 分析也不再保存不存在的待恢复消息，而是清理本轮输入并给出可读错误。
- 保留真正不确定发送的原安全锁，不降低重复发送保护。
- 网感姿势规则改为：仅固定 JSON 键名允许英文，所有内容值使用中文。
- 结构化回复已稳定结束 5 秒仍不合格时立即返回格式错误，不再空等四分钟。

## 经验教训

- 浏览器自动化中的点击返回值只表示事件已派发，不代表业务动作已发生；补点必须建立在可证实的无操作状态上。
- 明确未发送与可能已发送必须分开分类，否则防重复机制本身会制造无意义的长等待。
- 结构化输出提示不能同时禁止其固定键名；模型偶尔容错成功不代表规则没有冲突。
- 当页面已经给出稳定终态时，应尽早返回明确错误，不能继续消耗完整总超时。

## 2026-08-22 与访问保护协同补充

- AI 分析和网感姿势在取得独占任务槽后、打开页面前先检查全局访问保护；保护期间不会新建对话、上传、发送或执行清理点击。
- 等待回复阶段才出现保护时，会持久记录 `PROTECTION_PAUSED`。AI 分析保留已经发送的恢复记录；网感姿势保留旧的 8 个选项和当前选择，不把保护显示成普通分析失败。
- 两条链路继续使用共同的发送确认策略：只有输入、附件、消息数量和页面状态共同证明首次点击完全无效，才补点一次；任何不确定状态都禁止补点。
- 网感姿势仍只接受固定英文 JSON 键和恰好 8 条中文值；已结束但格式错误的回复快速返回准确原因，不等待完整超时。
- 隔离 Electron 注入保护状态后，AI 分析与网感姿势状态均正确回显，两个入口仍存在且没有卡在运行中；真实账号端到端仍等待 Hale 人工最小验证。
