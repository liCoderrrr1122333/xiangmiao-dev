# 耀创工坊 0.1.10 专属 Chrome 自愈加固记录

## 问题现象

- 收件人点击“查看窗口”后没有可见反馈，专属 Chrome 窗口不出现。
- 点击“检查登录”后无响应，或界面显示 `connect ECONNREFUSED 127.0.0.1:<port>`。
- Chrome 已登录后，软件可能因为失效的本地调试端口而无法读取页面状态。
- “检查登录”和“查看窗口”连续点击时，按钮可能长期停留在“打开中”。

## 根因

1. 旧版本只轮询 Chrome DevTools 端口，没有监听浏览器进程的启动错误和提前退出。
2. 软件异常退出、升级或电脑重启后，专属配置目录可能仍被旧 Chrome 进程占用；新进程会直接退出或转交给旧进程，因此不会监听新端口。
3. 旧端口文件可能已经失效，甚至可能被其他本地程序重新占用，不能据此直接关闭端口上的程序。
4. 界面没有独立的打开/检查忙碌状态，耗时 IPC 调用期间看起来像点击无效。
5. 并发操作通过序号忽略旧结果时，也错误跳过了“打开中”状态的释放。
6. 直接依赖 `PATH` 查找 `powershell.exe`，在被精简过环境变量的电脑上可能无法运行窗口和进程辅助逻辑。
7. 原生显示校正与登录成功后的隐藏命令并行执行时，较晚结束的显示动作可能覆盖隐藏动作。

## 解决方式

- 每次重建专属浏览器前，通过进程命令行精确匹配耀创专属 `--user-data-dir`，只清理对应 Chrome/Edge 进程树。
- 不再信任或连接旧端口来关闭浏览器，避免误伤占用相同端口的其他程序。
- 保留专属配置目录中的 Cookie、站点数据和账号状态，只清理运行期端口、PID、模式元数据。
- 仅在确认专属进程清理成功后删除 Chrome 锁文件；进程所有权未知时保留锁文件。
- 每个可用浏览器使用新端口重试两次；Chrome 失败后自动尝试 Microsoft Edge。
- 监听浏览器 `error` 和提前 `exit`，快速失败并进入下一轮恢复，不再空等 25 秒后显示底层连接错误。
- 将底层错误写入滚动诊断日志，界面只显示用户可执行的中文恢复提示。
- “查看窗口”和“检查登录”增加即时忙碌状态、旋转图标、超时边界和重复请求合并。
- “查看窗口”在后台检查期间保持可点击，可主动接管恢复；打开任务完成后无条件释放按钮状态。
- Windows PowerShell 优先使用系统目录中的绝对路径，不依赖用户 `PATH`。
- 原生显示/隐藏操作进入同一串行队列，以递增代次保证最后一次用户意图生效。

## 经验教训

- 本地调试端口只是临时能力，不能作为浏览器进程身份。
- 浏览器自动化必须同时管理进程、端口、配置锁、页面健康和界面反馈，缺少任意一层都会表现为“按钮无反应”。
- 恢复逻辑必须按专属配置目录确认进程所有权，不能按进程名或旧端口做宽泛清理。
- 忙碌状态的释放必须绑定任务生命周期，不能绑定可能被后续请求改变的结果序号。
- 网络、VPN、Google/OpenAI 登录策略仍属于外部条件；软件应保证失败可见、可恢复、可诊断，不能把外部服务可用性伪装成已成功。
