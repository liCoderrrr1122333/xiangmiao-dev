# 耀创工坊 0.4.0 后期处理与发布加固记录

## 发布范围

- 基线：`v0.3.1-stable`。
- 分支：`feature/0.4.0-post-processing`。
- 目标：增加可恢复、非破坏性的 JPG 后期处理工作流，并保持 ChatGPT 自动做图、并行调度和断点续做稳定。
- 保持不变：原图像素尺寸、红圈外保护、一键蒙脸、人脸与衣物配饰参考图、AI 分析回填、提示词快照、模型选择、1/2/3 路并行、失败识别、结果归档和专属 Chrome 登录资料。

## Graphify 调用链结论

最新依赖图覆盖 117 个文件，包含 1442 个节点、2686 条边和 110 个社区，未发现导入环。

关键链路为：

1. `App.tsx` 在点击开始做图时冻结后期处理开关，并通过 preload 把同一批次快照交给主进程。
2. `main/index.ts` 继续复用既有附件上传、发送确认、失败识别和并行调度，只改变生成结果的落盘目的地。
3. `postProcessingStore.ts` 把每张结果转换为尺寸核验通过的 JPG，串行更新版本化清单和精确任务检查点。
4. `PostProcessingWorkspace.tsx` 只读取降采样预览；每张图持有独立参数，并通过显式操作同步到其他已选图片。
5. `postProcessing.worker.ts` 与 `postProcessingEngine.ts` 使用确定性种子执行 WebGL/CPU 双路径预览和完整像素导出。
6. 导出成功后，主进程才把最终 JPG 写入桌面文件夹并返回 `resultArchive`；失败项继续留在临时区。
7. `chatGptBatchCheckpoint` 以任务编号而不是完成数量恢复，已经安全进入后期临时区的任务不会重复发送。

## 问题记录

### 1. 开启后期处理后仍可能提前进入最终归档

- 现象：旧流程在 ChatGPT 结果识别后立即保存到桌面并加入结果归档，没有“先挑选、再保存”的状态。
- 根因：结果检测、桌面保存和归档写入原本是一个不可分割动作。
- 解决：引入 `post-processing` 结果存储模式；开启时先写入 `D:\Yaochuang-Workshop\AppData\PostProcessing`，只在用户成功导出后加入最终归档。
- 经验：自动化任务的“生成完成”和用户认可的“最终成片”必须分开建模。

### 2. 图片格式、透明背景和像素尺寸不统一

- 现象：ChatGPT 或 API 可能返回 PNG、WebP、不同尺寸或带透明区域的图片，手机兼容性和后期输入不稳定。
- 根因：旧流程主要依赖扩展名和下载结果，没有把编码、解码和尺寸复核作为完成条件。
- 解决：所有生成结果统一转为质量 96% 的 JPG；透明区域铺白；写入临时文件后重新解码，核对 JPG 头尾、宽度和高度，再原子替换最终文件。
- 经验：文件写入成功不等于图片可用，断点完成标准必须包含重新解码和像素尺寸验证。

### 3. 异常退出后待处理图片无法可靠恢复

- 现象：软件关闭或崩溃后，未导出的图片和独立参数可能丢失，或者旧清单覆盖新状态。
- 根因：缺少版本化清单、备份和原子写入；并行任务也可能同时修改同一状态文件。
- 解决：使用主清单、备份清单、临时文件加原子替换，并以进程内事务队列串行化读取、落盘、参数更新、导出和清理。
- 经验：可恢复工作区必须让图片文件和元数据分别可验证，不能只依赖 React 内存状态。

### 4. 三路并行可能互相覆盖清单

- 现象：多个生成标签页接近同时完成时，后写入的清单可能丢掉先完成任务。
- 根因：每个通道都按读取到的旧清单生成新副本，没有统一提交顺序。
- 解决：所有后期存储操作经过同一事务队列；任务以稳定 `taskIndex` 去重和排序，完整落盘后才加入 `completedTaskIndices`。
- 经验：并行网络任务可以并发，持久化检查点必须串行提交或使用真正的事务。

### 5. 本地暂存失败可能导致 ChatGPT 重复生成

- 现象：ChatGPT 已经生成成功，但磁盘写入暂时失败时，旧重试层可能重新提交同一个远程任务。
- 根因：远程生成失败和本地持久化失败共享同一个重试结果。
- 解决：候选图片确认后，本地 JPG 暂存使用独立有限重试；远程任务不再重新发送，失败原因记录到对应任务。
- 经验：外部副作用已经成功后，只能重试本地幂等步骤，不能重做远程副作用。

### 6. 完整像素后期处理可能造成内存峰值

- 现象：多张大图同时执行完整像素滤镜和导出时，Data URL、像素缓冲和 JPG 结果会叠加占用内存。
- 根因：预览与导出没有分层，批量导出曾一次性准备全部完整尺寸图片。
- 解决：预览最长边限制约 1600px；最终导出按选中项逐张读取、处理、写入和释放，失败项隔离，下一项继续。
- 经验：桌面图像工具的内存上限应由“同一时刻处理几张完整图”控制，而不是只看文件体积。

### 7. 快速拖动滑块会出现旧预览覆盖新参数

- 现象：连续调整参数时，较慢的旧任务可能晚于新任务返回，使画面短暂回退。
- 根因：渲染结果缺少请求代次与取消语义。
- 解决：预览 Worker 使用请求 ID，切图、参数变化和组件卸载会取消旧任务；只有最新结果可以更新画面。
- 经验：高频交互任务不仅要防任务堆积，还要防乱序完成。

### 8. 部分导出后断点状态可能误判

- 现象：只导出部分图片后，已导出任务从临时清单移除；若仅以剩余清单推断完成任务，可能重复发送已成功任务。
- 根因：待处理项列表和批量完成检查点承担了两种不同语义。
- 解决：清单独立保留 `completedTaskIndices`；只删除成功导出的临时源图，未选中或失败项继续保留。
- 经验：资源生命周期和业务任务完成状态不能用同一个数组隐式表达。

### 9. 清单损坏会阻断第一次新任务

- 现象：主清单与备份同时损坏时，用户第一次点击开始做图可能直接报错；关闭后期处理的桌面直出批次也会被阻断。
- 根因：读取层正确拒绝猜测损坏数据，但调用层没有把“隔离损坏清单”转换为可继续的恢复路径。
- 解决：损坏清单改名隔离，无法确认归属的 JPG 永不模糊删除；开启后期处理时建立新批次，关闭时给出警告并继续桌面批次。
- 经验：安全拒绝和业务恢复需要同时设计，不能把底层保护异常直接抛给普通用户。

### 10. 1280×720 下右侧按钮可见但无法点击

- 现象：滚动到“归档”时，顶部做图面板覆盖标签栏，Playwright 报告点击被后期处理开关或张数控件拦截。
- 根因：右侧栏已经是滚动容器，内部做图面板又使用 `position: sticky`，形成重复固定层。
- 解决：做图面板随右栏正常滚动，标签栏继续在到达顶部后固定；增加几何重叠断言和真实点击回归。
- 经验：桌面最小分辨率验收必须点击所有滚动区控件，不能只检查截图没有横向溢出。

### 11. 高权限 IPC 依赖隐式的本地页面前提

- 现象：主窗口已经隔离和沙箱化，但 IPC 没有逐次确认调用者；如果未来误允许外部导航，preload 接口边界会变弱。
- 根因：安全边界只由窗口创建配置和 CSP 间接保证。
- 解决：阻止主窗口导航到非耀创工坊页面；所有 IPC 校验主窗口 WebContents、顶层 frame 和受信 URL；内置 ChatGPT 只允许网页写剪贴板，拒绝相机、麦克风、定位等设备权限。
- 经验：Electron 的导航、preload 和 IPC 必须形成三层独立边界，不能假设其中一层永远不会变化。

## 回滚与残余风险

- 回滚基线：`v0.3.1-stable`。
- 功能按存储、自动化接入、渲染、工作区、安全和测试拆分为独立提交，可逐项 `git revert`，不需要重置工作树。
- 极端超高分辨率图片仍受设备显存和内存约束；当前通过 1600px 预览、逐张完整导出、取消旧任务和 CPU 后备降低风险。
- ChatGPT 网页 DOM 仍可能由服务端更新；0.4.0 没有放宽模型、发送或结果识别规则，失败仍会停止并保留诊断。
- Google OAuth、验证码和人机验证继续由用户在专属 Chrome 中手动完成。
- 当前安装包未配置商业 Authenticode 证书，Windows 仍可能显示未知发布者或 SmartScreen 提示；正式大规模售卖前应配置可信代码签名证书。
