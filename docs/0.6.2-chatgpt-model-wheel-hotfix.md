# 耀创工坊 0.6.2 ChatGPT 模型菜单与画布滚轮修复

## 问题一：ChatGPT 模型无法选择

### 现象

ChatGPT 输入框右侧显示“高”或“5.5 高”，网页可以通过“高级 → 模型”查看模型，耀创工坊却提示页面没有模型选择器。

### 根因

ChatGPT 将原来的单层模型菜单改成了三级结构：质量入口、`高级` 分支、`模型` 子菜单。原适配器只处理质量入口后直接出现模型分组的结构，也没有把“5.5 高”识别为质量入口。

### 解决方式

- 分开识别质量标签、`高级` 分支、`模型` 分支和真实模型项。
- 对菜单最多执行三层、有限次数的语义遍历，不依赖坐标和哈希类名。
- 读取模型时不改变选择，结束后关闭菜单。
- 指定模型后重新打开菜单，通过选中项或“模型”行当前值二次确认。
- 增加与当前网页结构一致的本地专属 Chrome 夹具，连续执行 20 轮读取和关闭验证。

### 经验教训

网页入口显示的“高”是思考质量，不是模型名称。模型自动化必须把模式、菜单分支和模型值分层建模，并用真实层级夹具覆盖页面结构更新。

## 问题二：画布缩放带动左栏滚动

### 现象

鼠标位于原图画布时使用滚轮缩放图片，左侧工作区有时也会上下滚动。

### 根因

非被动滚轮监听仅绑定在 `<canvas>` 元素上。画布反馈层或其他覆盖元素接收滚轮时，事件会绕过该监听并继续触发左栏默认滚动。

### 解决方式

- 将非被动滚轮监听提升到画布视口，并在捕获阶段处理。
- 图片存在时执行 `preventDefault` 和 `stopPropagation`，只更新图片缩放。
- 缩放锚点限制在画布边界内，保留鼠标位置缩放和不同 `deltaMode` 兼容。
- 组件卸载时按相同捕获参数移除监听器。
- 增加画布本体、透明覆盖层和画布外区域三组 Playwright 验证。

### 经验教训

交互画布的滚轮边界应属于整个 viewport，而不是某个可能被覆盖的渲染节点；同时必须保留边界外容器的原生滚动行为。
