# 耀创工坊 0.1.6 专属 Chrome 恢复记录

## 问题现象

- 登录状态显示“暂时无法确认 ChatGPT 登录状态”。
- 自动流程持续显示“正在后台重新载入 ChatGPT”，但输入框没有恢复。
- 专属 Chrome 已经在后台运行，点击“查看窗口”却没有任何可见反应。

## 根因

1. 后台模式使用 Windows `ShowWindow` 隐藏 Chrome 后，`Process.MainWindowHandle` 会变成 `0`。旧逻辑再次显示时无法找到隐藏窗口句柄。
2. 复用可见 Chrome 时，窗口获取逻辑会先调用后台收纳逻辑，导致刚准备显示的窗口再次被隐藏。
3. ChatGPT 部分静态资源请求可能停留在不完整的 HTTP 缓存状态。普通导航会继续复用坏缓存，页面长期只有标题和 `<head>`，正文长度为 `0`。
4. 页面健康检查把“有标题和 HTML、但没有正文”的半加载页面误判为可用，因此不会触发恢复。
5. 自动化已经识别出登录页后仍会继续重载，造成“后台重新载入”的误导提示。

## 解决方式

- 使用 Windows `EnumWindows` 枚举专属 Chrome 的 `Chrome_WidgetWin_1` 顶层窗口，不再依赖 `MainWindowHandle`。
- “查看窗口”操作先立即恢复并显示窗口，再异步检查和恢复页面。
- 修正专属 Chrome 可见模式的复用条件，避免显示请求被后台逻辑覆盖。
- 对正文为空的 ChatGPT 页面执行 `Network.clearBrowserCache` 和 `Page.reload({ ignoreCache: true })`。
- 缓存恢复只清理 HTTP 缓存，不清理 Cookie、登录资料或本地用户数据。
- 收紧页面健康判断：必须出现有效正文、登录控件或输入框，只有标题的页面不再算可用。
- 明确识别到登录页后直接返回“需要登录”，不再进行无意义的后台重载。
- 增加 Chrome 崩溃恢复提示屏蔽参数，避免出现“要恢复页面吗？”窗口。

## 验证记录

- 自动化测试：40 项通过。
- 后台专属 Chrome：顶层窗口存在且不可见。
- 点击“查看窗口”：同一登录资料重新启动为可见模式，窗口成功显示。
- 隐藏窗口恢复：通过 `EnumWindows` 找到隐藏句柄并恢复。
- 故障注入：将 ChatGPT 正文清空后再次点击“查看窗口”，约 13.6 秒后正文恢复。
- 登录页识别：返回“专属 Chrome 需要完成登录”，不再进入后台重载循环。
- 登录资料：恢复过程未删除 Cookie 或专属 Chrome 用户目录。
- 正式安装包：`Yaochuang-Workshop-0.1.6-Setup.exe`，体积 120.30 MiB。
- 实际安装：安装返回码为 0，安装程序、卸载注册项和桌面快捷方式均为 0.1.6。
- 安装版故障注入：正文清空后约 12.3 秒恢复，窗口保持可见，登录状态返回明确结果。

## 经验教训

- Windows 隐藏窗口不能依赖 `Process.MainWindowHandle` 再次找回。
- 浏览器 URL、标题和 HTML 长度不能代表页面已经可交互，必须验证可见正文或核心控件。
- 网络恢复应区分 HTTP 缓存与登录资料，优先清理可再生缓存，保留用户身份状态。
- 用户主动点击“查看窗口”时，显示动作必须优先于健康检查和后台恢复。
