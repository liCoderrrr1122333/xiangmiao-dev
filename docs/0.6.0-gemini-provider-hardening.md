# 耀创工坊 0.6.0 Gemini 网页服务与稳定性加固记录

## 范围

- 新增 Gemini 官方网页服务商，不重写原有 ChatGPT 自动化。
- ChatGPT 与 Gemini 共用一个专属真实 Chrome 和持久化资料目录，使用独立标签页和会话状态。
- 服务商、模型、附件、提示词、数量、并行数和原图尺寸在开始做图时冻结。
- Gemini 支持登录检查、查看窗口、模型读取、原图分析、附件上传、发送确认、文本/图片结果识别、JPG 保存和 1/2/3 路并行。

## 已确认问题与修复

### Gemini 重定向被误判为加载失败

- 现象：官方页面已经完成跳转，但 Playwright 返回 `ERR_ABORTED`。
- 根因：导航被网页后续重定向替代。
- 修复：只在最终地址仍属于 Gemini 或 Google OAuth 时将该错误视为已恢复。
- 教训：不能只看一次导航 Promise，也不能对外部地址放宽信任边界。

### Gemini 页面偶发空白

- 现象：地址正确但页面没有输入框、登录入口或可用正文。
- 根因：Angular 壳层加载中断或浏览器恢复了空白标签页。
- 修复：后台执行一次有上限的 `about:blank` 清理和官方地址重载；Google OAuth 页面不自动刷新。
- 教训：恢复必须有次数上限，并保留人工登录边界。

### 服务商切换被旧异步结果覆盖

- 现象：切换 Gemini 后，较晚返回的 ChatGPT 登录或模型结果可能覆盖界面。
- 根因：异步请求缺少服务商序列校验。
- 修复：切换时递增登录和模型序列，只接受当前服务商的最新结果。
- 教训：服务商切换必须同时失效旧请求和旧状态。

### Gemini 指定模型可能误判版本

- 现象：`2.5 Pro` 和 `3.1 Pro` 可能被当成同一模型。
- 根因：模型别名逻辑无条件移除了版本号。
- 修复：两侧都含版本号时要求完全一致；只有网页一侧省略版本号时允许别名确认。
- 教训：模型验证宁可停止发送，也不能静默降级。

### 旧回复污染本轮失败判断

- 现象：新对话等待阶段可能读取页面最后一条旧失败回复并提前停止。
- 根因：失败检测没有应用发送前回复基线。
- 修复：只读取基线之后的新模型回复或当前可见告警。
- 教训：文本、图片和失败判断必须共享同一任务基线。

### 控制队列未等待 Gemini 查看窗口

- 现象：极端连续点击下，生成任务可能在 Gemini 查看窗口动作尚未结束时取得任务槽。
- 根因：任务槽只等待 ChatGPT 的 `show-window` 单飞键。
- 修复：任务槽同时等待 ChatGPT 和 Gemini 的查看窗口动作。
- 教训：共享浏览器资源需要跨服务商互斥，不应只按按钮名称推断资源边界。

### 诊断日志隐私覆盖不足

- 现象：日志已脱敏 Token 和 Cookie，但可能保留邮箱、账号 ID 和 Windows 用户目录名。
- 根因：脱敏规则未覆盖这些字段。
- 修复：增加邮箱、结构化账号标识、`C:\\Users\\用户名` 与 file URL 用户目录脱敏。
- 教训：商业诊断日志必须保留操作证据，同时默认隐藏身份和本地隐私路径。

### Windows 打包目录被安全扫描短暂占用

- 现象：Electron 解压完成后，`win-unpacked.tmp` 立即重命名时报 `EPERM`；数秒后手动重命名成功。
- 根因：Windows 实时安全扫描与 electron-builder 的即时重命名发生竞态，不是编译或应用代码失败。
- 修复：`dist:win` 直接使用项目已安装的 `node_modules/electron/dist`，绕过重复下载解压和竞态窗口。
- 教训：发布脚本必须在默认安全软件开启的环境中稳定运行，不能要求用户关闭 Defender。

### 打包版验证与开发实例争用同一 AppData

- 现象：打包版 Playwright 启动后退出，并出现缓存拒绝访问和单实例交接。
- 根因：先前启动的项目 Electron 开发实例仍占用 `D:\\Yaochuang-Workshop\\AppData`。
- 修复：测试前只关闭路径明确属于当前工作树的 Electron 进程，不结束用户普通 Chrome；随后打包版验证通过。
- 教训：安装验证必须先隔离进程占用，不能把单实例锁或缓存锁误判为产品启动故障。

### Electron Fuse 与正式包自动验收冲突

- 现象：关闭 Node 主进程检查参数后，Playwright 无法启动打包版 Electron。
- 根因：Playwright Electron 驱动依赖 `--inspect=0` 建立主进程测试连接。
- 修复：保留 Node CLI inspect，继续禁用 `ELECTRON_RUN_AS_NODE` 和 `NODE_OPTIONS`，并启用 Cookie 加密、ASAR 完整性和仅从 ASAR 加载。
- 教训：源码保护只能在可测试、可恢复的边界内加强，不能以失去正式包验收能力换取表面安全。

## 验证

- 单元与源码契约测试：覆盖登录、模型、发送基线、失败分类、队列、并行与数据兼容。
- Gemini fixture：登录/退出、模型读取与选择、附件、发送确认、额度失败、诊断脱敏、3 标签提示词隔离。
- 官方 Gemini 表面检查：识别页面与人工登录边界，不自动点击 Google 登录或安全验证。
- Chrome 专项：管道主通道、端口后备、窗口隐藏/显示、标签隔离和 20 轮恢复。
- 回归：自适应画布、一键蒙脸、连续批次、JPG 方向与原图尺寸、结果持久化、Electron 安全壳层。
- 全量测试：128/128 通过，`verify:chrome`、`verify:gemini`、官方 Gemini 未登录表面检查和生产构建通过。
- 安装验证：全新安装、0.5.1 升级到 0.6.0、0.2.3 升级到 0.6.0 均通过；AppData 与专属 Chrome 登录状态保留。

## 源码保护

- Electron 无法保证源码绝对不可恢复。
- 正式包只收录 `dist`、`dist-electron` 和运行所需元数据，并使用 ASAR。
- 发布验收必须确认没有 `.ts`、`.tsx`、`.map`、测试、Git 元数据和开发文档。
- 已启用 Cookie 加密、嵌入式 ASAR 完整性和 `OnlyLoadAppFromAsar`，并关闭 `ELECTRON_RUN_AS_NODE` 与 `NODE_OPTIONS`。
- 为保留正式包 Playwright 验收能力，Node CLI inspect Fuse 保持开启；它不是源码保护的主要边界。
- 不对整个应用启用高风险混淆，避免破坏网页选择器、堆栈诊断和启动性能。

## 残余风险

- ChatGPT 与 Gemini 是第三方网页，页面结构、模型名称、账号策略和生成能力会变化。
- Google 登录、验证码、人机验证与账号安全步骤只能由用户手动完成。
- 未登录真实 Gemini 账号时只能完成官方未登录页面与本地 fixture 验证，不能诚实声称真实账号完整生成已通过。
