# 耀创工坊 ChatGPT 自动化速度与访问保护优化

更新时间：2026-08-22

状态：版本仍为 `1.1.2`；2026-08-22 保护暂停与恢复补充修复已重新打包并完成同版本覆盖安装，未提交代码。

## 问题现象

- 页面已经显示当前可用模型，但批量任务仍可能按旧的固定模型失败。
- 健康页面每次提交仍等待 60 秒以上，三路任务整体效率偏低。
- 已发送任务在没有生成进展时可能长时间停留在等待状态。
- 单个通道结果不确定时，会停止其他仍健康的通道。
- 访问保护重复出现时，冷却截止时间可能被持续向后顺延。
- 批次摘要把所有未完成任务都写成失败原因，但运行指标仍显示失败为 0。

## 根因

1. 工作模式同时写入固定模型和思考强度，模式选择会把已读取的网页当前模型重新覆盖为旧模型名。
2. 提交节奏沿用了过度保守的 60/90/120 秒档位，健康状态也承担了恢复态的等待成本。
3. 结果等待只有较长的总超时，缺少“完全无进展”和“回复已结束但无图片”两类提前退出条件。
4. 已发送但未识别到结果被当作全局故障，调度器无法只隔离当前通道。
5. 每次再次识别到访问保护都会重新计算五分钟，形成滑动冷却。
6. 监控模型没有单独表示排队任务和待人工确认任务。

## 解决方式

- 默认模型改为 `follow-current`；快速、均衡、稳定高质只分别表达低、中、高思考强度，不再覆盖网页当前模型。
- 保留用户显式选择模型时的严格门禁，不静默切换模型，也不静默降低思考强度。
- 自适应提交节奏调整为健康 `12s`、降速 `20s`、恢复 `30s`。
- 三路标签页仍按顺序建立，但启动错峰由每路 `30s` 收敛为 `10s`；三路准备等待由约一分钟降为约二十秒，发送仍受独立的自适应门禁约束。
- 结果等待使用同一不可变开始时间：
  - 连续 `60s` 没有任何生成信号时提前停止。
  - assistant 回复已经稳定结束但没有图片时，再观察 `15s` 后停止。
  - 无论页面如何变化，单次生成最长等待 `180s`。
- 已发送但结果不确定的任务标记为 `MANUAL_REVIEW`，只隔离当前通道；不再写入会阻塞全批次的发送不确定冷却，其他已发送或健康通道继续等待和保存。
- 访问保护使用固定冷却截止时间；同一冷却窗口内重复信号不能向后延长截止时间。
- 运行面板新增“待执行”和“待确认”，最终摘要改为“首个未完成原因”，区分待确认、真实失败和剩余排队任务。

## 经验教训

- 模型设置应同步网页真实状态，工作模式不应重新制造固定模型依赖。
- 超时必须使用不可被轮询或重复错误重置的绝对截止时间。
- “已经发送但结果未知”不是“确定失败”，也不应自动扩散为整个批次停机。
- 访问保护只能安全等待和恢复，不能通过密集点击或滚动延长冷却来尝试绕过。

## 2026-08-22 保护状态与恢复上限补充修复

### 新现场证据

- 正式脱敏日志显示：AI 分析于 `05:50:01` 提交并在 `13.6s` 后完成；网感姿势于 `05:50:31` 提交并在 `10.6s` 后返回 8 条；三路批次于 `05:51:32` 启动，`05:52:03` 又提交做图，`05:52:33` 两个通道同时读到对话访问保护。保护前约 92 秒内跨三个功能提交了 3 次。
- `05:51:43` 与 `05:52:13` 连续出现模型和高思考强度确认，说明并行标签页准备仍包含昂贵的菜单操作。
- 另一组网络故障日志中，输入框后台恢复从 `10:23:15` 持续到 `11:02:36` 才由 `ERR_NETWORK_CHANGED` 打断，约 39 分 21 秒。根因不是三分钟生成等待，而是 CDP Escape/页面恢复调用没有统一硬上限。
- 保护期间出现的 `show-window` 事件均来自用户主动查看窗口，不计作软件自动恢复点击。

### 本轮根因

1. 访问保护只有冷却时间，没有独立持久状态，批次最终汇总可能把安全暂停写成失败或待人工确认。
2. 冷却检查失败后仍可能重新进入五分钟循环；并行 worker 降为一路后，其他 worker 会直接退出，无法逐步恢复二路和三路。
3. 已发送任务看到保护提示时立即抛出额度异常，统一异常清理又会操作输入框，无法继续只读等待并保存已经生成的结果。
4. AI 分析、网感姿势和正式做图虽然共享发送节奏，但休息计数只按成功图片增加，分析与姿势提交没有进入同一连续提交预算。
5. 输入框恢复内部虽有若干局部等待，CDP 菜单关闭和整个恢复流程仍可能永久悬挂。

### 本轮解决方式

- 新增持久 `PROTECTION_PAUSED`、`RECOVERING_ONE_LANE`、`RECOVERING_TWO_LANES` 状态；保护暂停不再归类为 `FAILED` 或 `MANUAL_REVIEW`。
- 同一保护事件只设置一次固定五分钟截止时间。到期仅自动检查一次、最多确认一次“明白了”；仍受保护时清除自动截止时间并等待人工“检查恢复”，不再滚动续期。
- 恢复通过后先单路完成一个健康任务，再放开二路；二路继续累计健康结果后才恢复用户选择的三路。等待中的 worker 不再永久退出。
- 保护出现后，未发送任务保留为 `PROTECTION_PAUSED`；已发送任务继续只读轮询当前页面并尝试保存，不清理输入框、不刷新、不重发。
- AI 分析、网感姿势和正式做图均在打开页面前执行保护门禁，并共享“已提交次数”休息预算。
- 同一页面、同一模型和同一思考强度的已验证配置在 30 分钟内直接复用，后续任务不再打开模型菜单。
- CDP Escape 每次命令限制 `1.5s`，完整输入框后台恢复限制 `65s`；不再出现几十分钟无法返回的假等待。
- 新增任务阶段诊断：输入框、新对话、配置、附件、发送确认、结果识别和本地保存分别记录耗时，后续真实人工验证可直接比较瓶颈。
