# 耀创工坊 0.1.4 商业稳定优化记录

## 自动化页面可能无限等待

- 现象：ChatGPT 已明确失败，耀创工坊仍显示正在等待；个别页面脚本不返回时，外层轮询超时也无法生效。
- 根因：自动化关键路径仍存在未设置硬超时的 `executeJavaScript` 调用，批量单张失败也没有尝试次数上限。
- 解决：所有页面脚本统一经过限时包装；单张最多尝试 3 次，批次总时限 2 小时；补充中文图片生成失败文案识别。
- 经验：轮询总时限不能替代单次异步调用时限；重试必须同时具备次数上限和明确终止状态。

## ChatGPT 已返回分析文本但软件未写入

- 现象：ChatGPT 页面已经生成原图分析，软件仍提示没有可用文本。
- 根因：分析发送后没有强制验证 ChatGPT 是否接收；延迟结果恢复失败时会过早删除待恢复记录。
- 解决：分析发送必须确认新用户消息，只在输入框完整保留且没有新消息时补发一次；待恢复记录保留 24 小时，恢复未完成时不重复上传或发送。
- 经验：网页自动化必须把“点击成功”和“服务端接收成功”视为两个状态，并为延迟响应保留可恢复证据。

## 批量任务中断后可能重复生成

- 现象：软件退出或任务暂停后，再次开始只能建立新批次，无法可靠区分已保存与缺失图片。
- 根因：批量进度仅保存在进程内存中。
- 解决：新增独立的批量检查点，以提示词、素材内容、目标张数和原图尺寸生成任务指纹；仅在指纹完全一致时从缺失序号继续。
- 经验：恢复状态应与项目数据分离并保持向后兼容；已保存文件是完成任务的唯一依据。

## 生成图片尺寸一致性

- 现象：ChatGPT 可能返回与原图宽高不同的结果。
- 根因：网页图片模型的输出尺寸不受本地项目精确像素约束。
- 解决：保存前按原图像素宽高执行高质量归一化；临时文件和最终正式文件分别解码校验，任何不一致都不计为成功。
- 经验：界面宣称尺寸一致之前，必须校验最终落盘文件，而不是只信内存中的尺寸字段。

## 1280x720 布局退化和底栏遮挡

- 现象：1280x720 下三栏变成约 5200px 的单列；1024x768 最后内容曾被状态栏遮挡。
- 根因：响应式断点在 1280px 直接切换单列，小窗口仍按 66px 顶栏计算工作区高度，Electron 最小窗口高度还大于 720px。
- 解决：正式最低分辨率 1280x720 保持三栏；1179px 以下才切换单列，使用实际 164px 顶栏高度为工作区和状态栏预留空间，并将最小窗口约束调整为 1024x600。
- 经验：桌面生产力工具的断点应由任务上下文是否能同时保留决定，不能套用普通网页的单列策略。

## 视觉层级与可访问性

- 现象：右侧存在多套就绪状态；设置复选框异常拉伸；空画布提示可点击但实际不能点击。
- 根因：状态组件重复，通用表单样式作用于复选框，画布缺少上传点击和键盘路径。
- 解决：保留做图操作区作为唯一权威状态；删除未再使用的状态组件；修复复选框尺寸；补充空画布上传、方向键移动红圈、弹窗焦点约束和 Esc 关闭。
- 经验：商业工具的高级感首先来自状态层级、文案一致和可恢复交互，而不是增加渐变或装饰。

## 打包依赖与体积

- 现象：第一次瘦身构建后的主进程存在，但主窗口和渲染进程没有启动。
- 根因：工作区 `node_modules` 是指向旧项目的目录联接，electron-builder 沿真实路径解析时漏带了 `jszip` 的传递依赖。
- 解决：解除目录联接但保留原目标目录，按锁文件在当前 D 盘工作区执行干净安装；前端依赖保留为开发依赖，由 Vite 打入渲染产物，正式包只携带 `jszip` 运行链。
- 经验：安装包验证不能止于构建成功，必须从最终解包程序确认主进程、渲染进程和主窗口全部出现，并核对 `app.asar` 的实际依赖。
- 体积：安装包从 135,215,702 字节降到 125,885,177 字节，减少 9,330,525 字节（8.90 MiB，6.90%）。
