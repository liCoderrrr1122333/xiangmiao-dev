# 耀创工坊 0.6.18 网感姿势重新生成模式热修复

日期：2026-08-14

## 问题现象

- 用户先使用网感姿势生成提示词，再进入金色微调窗口保存自定义提示词后，切换到另一个网感姿势并点击“一键生成提示词”，右栏会变成空白的“自定义”提示词框。
- 提示词区域下方仍显示“生成与导出选项”折叠行，但主要生成、复制和微调入口已经位于工作流主按钮与提示词标题栏，该折叠行重复且不明显。

## 根因

- 保存微调会正确把项目 `outputMode` 设置为 `custom`。网感姿势切换会使旧提示词签名失效，但不会改变该模式。
- 主流程“一键生成提示词”随后沿用 `project.outputMode` 调用 `PromptBuilder.build`；自定义模式按原设计返回空白草稿，等待用户手填，因此出现“自定义 + 0 字符”。
- “生成与导出选项”是旧模式切换器及次级命令集合。在主工作流已经承担生成、标题栏承担复制、金色入口承担微调后，它成为重复入口，并且允许项目再次停留在自定义模式。

## 解决方式

- 主流程“一键生成提示词”现在明确退出旧自定义模式，将项目模式恢复为 `regional`，并始终调用 `PromptBuilder.build(project, 'regional')`。
- 自定义提示词只能由“提示词自定义微调”窗口在用户点击“保存修改”后产生；切换网感姿势再生成时，必定得到包含最新姿势的非空系统提示词。
- 删除“生成与导出选项”折叠行、模式切换器和对应死样式。保留主流程生成按钮、提示词标题栏复制、金色微调、发送快照及结果归档。
- 未修改 ChatGPT/Gemini 自动化、附件策略、Provider、IPC、保存格式、登录资料或用户项目结构。

## 经验教训

- “自定义”是已生成提示词的编辑结果，不应成为主流程重新生成的输入模式；系统重新生成必须显式选择系统模式，不能继承上一次编辑状态。
- 动态选项失效不能只验证签名阻断，还要覆盖“旧草稿类型 + 新选项 + 重新生成”的完整状态组合。
- 删除重复入口时必须先确认其命令在主流程中仍有明确归属，再同时清理组件参数、图标导入、样式和测试契约。
