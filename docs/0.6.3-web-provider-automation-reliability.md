## 现象

1. Gemini 已上传图片并写入提示词，模型选择也可见，但右下角箭头没有被点击，分析无法自动发送。
2. Gemini 偶尔返回“选项 A / 选项 B”双回复，旧读取器无法稳定提取完整 JSON，四个分析字段不能完整回填。
3. ChatGPT 菜单能显示并切换到 `GPT-5.5`，软件仍报“指定模型当前不可用”，并在上传前停止。
4. 本次真实回归期间 Google 将 Gemini 重定向到“暂不支持所在地区”页面；旧逻辑会把落地页的营销容器误认为回复节点并等待到超时。
5. Gemini 普通回复正文位于 `message-content`，其后还有空的 `response-container-footer`；旧读取器按 DOM 末项取值，最终得到 0 字。
6. Gemini 当前文件入口在一次选择多张图片时只稳定挂载一个预览；旧逻辑仍把文件输入事件视为上传完成，可能出现“网页有过预览、模型却没有收到附件”。

## 根因

### Gemini 发送

- 当前 Gemini 的实际发送控件位于 `data-test-id="send-button-container"`，按钮的无障碍名称是“发送”。
- 旧选择器只匹配“发送消息 / 提交 / send message / submit”，因此漏掉真实按钮并退回 Enter；当前富文本输入区不保证 Enter 能提交。

### Gemini 回复

- 双回复实验使用 `response-selection-panel`，不属于旧的 `model-response` 或 `response-container` 规则。
- 页面同时暴露双回复叶节点及祖先容器；祖先文本合并了两份 JSON，不能作为单一结构化结果解析。
- 待恢复 URL 在路由跳转前保存，可能只记录 `/app` 根地址，无法可靠回到同一轮结果。
- 普通回复祖先同时包含正文、无障碍标签、页头和空页脚；按宽泛的 `response-container` 列表取最后一项会选中空页脚。

### Gemini 附件与图片模式

- `DOM.setFileInputFiles` 成功只证明浏览器接收了文件选择，不证明 Gemini 已生成可发送的附件实体。
- 当前 Gemini 文件入口对多文件批量设置不稳定；两张素材必须逐张选择，并分别等待真实预览稳定。
- “制作图片”菜单在模型切换和页面重挂载后可能延迟出现，单次点击后等待 350ms 不足以覆盖真实页面。

### ChatGPT 模型确认

- 当前输入区将 `GPT-5.5` 简写为 `5.5`，而三级菜单叶项不总是保留 `aria-checked`。
- 旧逻辑只接受叶项选中标记，忽略输入区模型胶囊和父级“模型”栏已经变化的证据。
- Radix 菜单在部分页面状态下不接受脚本合成点击，需要 Chrome DevTools Protocol 发送可信鼠标事件。

## 解决方式

- Gemini 优先点击 `send-button-container` 内的真实按钮，兼容精确“发送 / Send”标签，保留一次有证据的安全重试和发送接受确认。
- 文本结果至少稳定三轮，并允许调用方提供“完整正文”谓词；原图分析只在四个核心字段均为非空有效值时回填。
- 双回复存在时只读取独立 `response-selection-panel` 叶节点，不读取合并祖先；普通回复继续沿用原选择器。
- 普通回复优先读取 `model-response message-content`，其次读取结构化正文，排除空页脚和用户提示词回显。
- 待恢复记录读取页面内 `location.href`，保存真实 `/app/<会话ID>`；异常出口也会再次刷新。
- 附件必须出现可见且已加载的图片/画布、关闭附件控件或明确“已上传”标记，并持续稳定六轮后才能发送；仅有 file-input 事件不再算成功。
- 多附件改为逐张上传、逐张确认，最终再核对总数；“制作图片”菜单允许两次有界重开，每次等待真实菜单项挂载。
- Gemini 明确回答“没有收到/上传附件”时立即归类为 `attachment-missing`，分析流程会清除错误恢复记录并在新对话内自动重试一次。
- ChatGPT 增加模型身份等价规则，使输入区 `5.5` 与菜单 `GPT-5.5` 可严格对应，但不同 5.6 分支仍不会混淆。
- 模型确认失败时启用有界可信点击兜底：打开输入区模型胶囊、进入“高级 / 模型”分支、读取真实选中态、点击目标并重新读取胶囊确认。
- 保留“指定模型未确认就不上传”的安全边界，不增加静默降级。
- Gemini 地区限制被识别为全局不可重试状态；登录检查、原图分析和生成流程会快速给出明确提示，不再等待 150 秒或读取营销示例。
- 共享批量调度器同步识别 Gemini 地区限制：首次失败立即熔断并保留缺失任务，不再做三次无意义重试。

## 经验教训

1. “模型已经切换”与“叶菜单存在选中属性”不是同一件事，最终确认应优先读取发送入口附近的当前模型状态。
2. 真实网页的脚本点击不总是可信事件；关键菜单需要 DOM 定位与 CDP 点击分层实现。
3. A/B 实验页要读取最小独立回复节点，不能让祖先容器合并多份结构化结果。
4. 发送成功后应保存路由稳定后的会话 URL；失败恢复记录必须在异常出口再次刷新。
5. 网页营销落地页也可能包含 `response` 类名，必须先识别服务不可用状态，再进行回复解析。
6. 文件输入事件、预览出现和服务端附件可用是三个阶段；关键发送必须等待稳定的真实预览，多个文件要逐个确认。
7. 回复读取应优先选择语义最小正文节点，空页头、页脚和祖先容器都不能参与“最新回复”排序。
