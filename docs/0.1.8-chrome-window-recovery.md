# 耀创工坊 0.1.8 专属 Chrome 窗口恢复记录

## 问题现象

- 首次安装并切换到专属 Chrome 后，软件提示需要完成登录。
- 点击“查看窗口”后，Chrome 窗口只在主屏幕最左侧露出很窄的一部分，标题栏位于屏幕外，无法正常拖动。
- 在明确处于未登录页面时点击做图，状态仍先显示“正在后台恢复 ChatGPT 自动窗口”，容易被误认为自动化损坏。

## 现场证据

- 主屏幕工作区：`0,0 - 1536,912`。
- 故障窗口坐标：`Left=-1025, Top=0, Right=33, Bottom=896`。
- 屏幕内仅剩 33 像素宽度，窗口样式仍包含正常标题栏和可调整边框。
- ChatGPT 页面地址为 `https://chatgpt.com/`，页面已完整加载，并明确包含“登录、免费注册、Sign in”，属于正常未登录状态。
- 同一 Chrome 进程内存在两个 `Chrome_WidgetWin_1` 顶层窗口：主窗口带标题栏和可调整边框，辅助窗口无标题栏且不可拖动。

## 根因

1. 后台 Chrome 使用了 `--window-position=-32000,-32000`。Chrome 将离屏位置写入专属用户配置，之后切换到可见模式时继续恢复旧坐标。
2. 原来的显示逻辑只执行恢复和置前，没有检查窗口与当前屏幕工作区的交集，也没有保证标题栏可见。
3. 原生显示逻辑只按 `Chrome_WidgetWin_1` 类名筛选，把 Chrome 内部无标题栏的辅助窗口也强制显示，辅助窗口可能挡在主窗口前方。
4. 做图入口已经检测到登录页，但仍无条件进入一次输入框恢复流程，导致状态提示与真实原因不一致。

## 解决方式

- 移除后台启动的离屏坐标参数，后台模式仅使用最小化和原生隐藏。
- 专属 Chrome 建立调试连接后立即执行显示或隐藏，减少首次启动闪现。
- “查看窗口”先恢复窗口状态，再读取 Win32 窗口矩形和主屏幕工作区。
- 当可见宽度不足 320 像素、可见高度不足 160 像素或标题栏不在可拖动范围内时，按当前工作区自动计算尺寸并居中。
- 可见模式主动隐藏无标题、无标准边框的 Chrome 辅助窗口，只恢复带 Windows 标准标题栏的浏览器窗口；Google 等正常登录弹窗仍可显示，后台隐藏仍覆盖专属进程的全部 Chrome 窗口。
- 主页面置前后立即清理一次辅助窗口，并在 350 毫秒后复查，覆盖 Chrome 聚焦时重新弹出内部辅助层的时序。
- 登录页已明确出现时，做图入口直接返回登录提示，不再显示“后台恢复输入框”。

## 验证结果

- 故意把窗口设置为 `Left=-1025` 后调用新版显示逻辑，恢复坐标为 `Left=238, Top=8`，窗口完整回到 `1536×912` 工作区。
- 全新后台配置启动坐标为 `Left=10, Top=10`，状态为 `minimized`，不再出现 `-32000` 持久化位置。
- 后台窗口 `isVisible=false`、`isMinimized=true`。
- 安装版从界面点击“查看窗口”后，主窗口保持标准标题栏和可调整边框，Chrome 内部辅助窗口不再被强制显示。
- `node scripts/verify-chrome-window-recovery.mjs` 真实启动隔离 Chrome：初始主窗口为 `Left=10, Top=10`；注入 `Left=-1025` 后恢复为 `Left=239, Top=8`；可见辅助窗口数量为 0。
- 保留旧配置覆盖安装后再次注入 `Left=-1025`，安装版恢复为 `Left=238, Top=8`；无标题辅助窗口仍存在但 `Visible=false`。
- 全新卸载并删除应用数据后，安装前不存在应用数据目录；首次启动为空项目、0 张参考图，后台 Chrome 顶层窗口可见数为 0。
- 全新配置点击“查看窗口”后主窗口为 `Left=10, Top=10`，标准标题栏与可调整边框正常；继续选择 Google 登录后进入真实 `accounts.google.com` 页面，窗口仍可见、可拖动且无辅助层遮挡。
- `npm test`：44 项测试全部通过。

## 经验教训

- 隐藏真实浏览器窗口不能依靠离屏坐标，因为 Chromium 会持久化窗口位置。
- “显示窗口”必须验证可见区域和标题栏，而不能只调用 restore/show。
- 登录未完成和页面结构异常是两类状态，自动化提示与恢复策略必须分开。
