# 耀创工坊 0.6.20 提示词素材职责收敛

日期：2026-08-14

## 问题现象

- 旧提示词在任务目标、附件说明、发型优先级、穿搭规则、姿势规则和负面限制中反复描述同一素材职责，容易让模型把重复句误读为多个并列目标。
- 上传穿搭参考图后，原图理解中的场景、姿态或面部朝向可能与穿搭替换目标同时进入提示词，削弱衣物参考图的约束。
- 选择网感姿势后，旧的原图姿态保护语句仍可能与新姿势并存；没有穿搭参考图时，又需要明确恢复主垫图原有穿搭，不能沿用穿搭替换分支。
- 操作指南仍把妆容、表情归给人脸参考图，并在末尾重复核心规则，与正式提示词的新职责边界不一致。

## 根因

- 人脸、发型、穿搭和姿势规则由多个独立片段逐步叠加，缺少按素材组合选择互斥分支的统一出口。
- 旧文案使用多个“最高优先级”和相似保护句强调同一要求，增加了长度，却没有增加可执行信息。
- 操作指南与正式提示词分别维护，提示词职责变化后没有同步收敛旧说明。

## 解决方式

- 将正式提示词稳定为任务目标、附件职责、原图理解、穿搭规则、可选姿势规则、融合要求、保护边界、最终检查和负面限制；每类职责只保留一个权威段落。
- 身份唯一来自全部人脸参考图中的目标男生；发型唯一来自标记为主参考图的人脸参考图。人脸参考图中的衣物、背景和姿势不再作为依据。
- 根据是否上传穿搭参考图、是否选择网感姿势形成四种互斥分支：
  - 无穿搭、无姿势：使用完整原图理解，全部穿搭和身体姿态保持主垫图原样。
  - 无穿搭、有姿势：使用场景、面部朝向、光影妆容与画质，已选姿势替代原图姿态；穿搭款式仍来自主垫图。
  - 有穿搭、无姿势：原图理解只继承光影、妆容与画质；指定穿搭来自对应参考图，未指定穿搭和身体姿态保持主垫图原样。
  - 有穿搭、有姿势：原图理解只继承光影、妆容与画质；指定穿搭来自对应参考图，已选姿势替代原图姿态，并只为姿势适配调整必要褶皱和遮挡。
- 删除提示词包装层对素材职责的重复解释；ChatGPT 与 Gemini 仍按现有顺序上传附件、确认提示词并要求直接返回图片。
- 同步更新提示词有效性签名、操作指南和 UI 验收断言；没有修改 Provider、IPC、附件文件集合、保存格式、模型选择、高思考强度门禁或登录资料。

## 经验教训

- 提示词的重点不是反复强调优先级，而是让每种素材只有一个明确职责，并让互斥条件只生成一个分支。
- 没有穿搭参考图并不等于缺少穿搭规则，必须显式回退到主垫图原有穿搭；有穿搭参考图时则只替换被指定目标。
- 姿势替换和穿搭替换会共同影响衣物褶皱与遮挡，允许范围应在姿势分支中一次说明，避免在保护规则里再次产生冲突。
- 操作指南、提示词签名和 UI 自动化断言必须与正式提示词同时更新，否则旧说明会在人工流程中重新引入干扰项。
