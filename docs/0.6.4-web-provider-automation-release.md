# 耀创工坊 0.6.4 网页 Provider 自动化修复与安装包发布

日期：2026-08-09

## 状态与边界

- 本次将已完成真实回归的 ChatGPT / Gemini 网页自动化可靠性修复升版为 `0.6.4`，并生成 Windows NSIS 一键安装包。
- 没有提交源码，也没有安装新版本；当前系统已安装程序仍为 `0.6.3.0`。

- 安装包、测试产物和验证用户目录均位于 D 盘。

## 现象

1. Gemini 能选择模型和写入提示词，但新版发送按钮无法稳定点击，分析结果不能完整回填。
2. Gemini 的双回复、正文节点和多附件预览结构发生变化，旧读取器可能选到合并祖先、空页脚或仅把文件输入事件误判为上传成功。
3. ChatGPT 已切换到 `GPT-5.5`，旧逻辑仍可能因为输入区显示简写 `5.5` 而误报模型不可用，并在上传前停止。
4. Google 将 Gemini 路由到地区限制页面时，旧逻辑可能继续等待或误读营销内容。

## 根因

- Gemini 当前发送控件使用 `send-button-container` 和“发送”标签，旧选择器没有覆盖。
- Gemini A/B 双回复、`message-content` 正文和附件实体需要按最小语义节点及稳定预览判断，不能依赖宽泛祖先或 file-input 事件。
- ChatGPT 菜单叶项不总保留选中属性，输入区模型胶囊还会省略 `GPT-` 前缀；部分 Radix 菜单需要 CDP 可信鼠标事件。
- 地区限制属于 Provider 全局终止状态，不应进入普通重试或回复解析。

## 解决方式

- Gemini 优先定位真实发送按钮，并保留发送接受证据和一次有界安全重试。
- 分析只在核心字段完整后回填；双回复只读取独立叶节点，普通回复优先读取 `message-content`，排除用户回显、空页脚和合并祖先。
- 多附件改为逐张上传、逐张等待真实预览稳定；附件缺失时清理错误恢复记录并在新对话有界重试。
- “制作图片”菜单允许两次有界重开；待恢复 URL 记录路由稳定后的真实会话地址。
- ChatGPT 严格等价识别 `GPT-5.5` 与输入区 `5.5`，必要时使用 CDP 可信点击重新选择并复核；仍禁止静默降级。
- Gemini 地区限制被识别为全局失败，批量任务第一次遇到即停止并保留断点，不产生伪成功结果。

## 经验教训

1. 模型菜单选中态、输入区模型标签和网页实际发送模型必须交叉确认，不能只依赖单个 DOM 属性。
2. 文件输入成功、预览出现和 Provider 真正收到附件是不同阶段，必须逐层取得可观察证据。
3. 回复解析应选择最小语义正文节点，并先识别终止状态，再解析业务结果。
4. 外部服务地区限制要在调度层熔断，保留断点比无意义重试更可靠。
5. 发布验证要从最终 `app.asar`、EXE 版本、哈希和安全扫描反查，不只依赖源码版本号或安装包文件名。
