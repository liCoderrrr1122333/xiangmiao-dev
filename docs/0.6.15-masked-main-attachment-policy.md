# 耀创工坊 0.6.15 红圈蒙脸附件策略修复

日期：2026-08-14

## 问题现象

- 用户上传衣物穿搭参考图后，ChatGPT 正式做图输入区同时出现未遮挡原图、红圈蒙脸主垫图、人脸参考图和衣物参考图。
- 用户要求正式做图只能上传已经完成红圈蒙脸的主垫图，未遮挡原图不得发送给 ChatGPT 或 Gemini。

## 根因

- 这不是衣物参考图面板重复上传原图，而是 `0.6.9` 为修复当时的“原图遗漏”问题，主动把 `mainPath` 和 `circlePath` 同时写入统一自动化附件数组。
- 导出 manifest、ChatGPT 输入框说明和操作指南也沿用了“双主图”策略，因此每次加入穿搭参考图时，未遮挡原图仍会按既定顺序上传。
- 发送清单只要求主图、红圈、参考图和提示词，没有把有效的一键蒙脸结果作为发送前硬门禁；关闭蒙脸后仍可能进入打包流程。

## 解决方式

- ChatGPT 与 Gemini 共用的自动化附件数组改为从 `01_红圈蒙脸主垫图.png` 开始，只追加人脸、衣物和配饰参考图。
- 未遮挡原图保留为 `00_仅本地原图备份`，继续用于原始像素尺寸、项目恢复和结果校验，但不进入 `automationUploadFiles`，也不进入任何网页 Provider 的上传参数。
- 发送前要求 `faceOcclusionEnabled` 与有效蒙版栅格同时存在；否则在上传附件前明确停止并提示先执行“一键蒙脸”。
- ChatGPT 和 Gemini 的输入框说明、操作指南、导出编号与 manifest 同步改为单一红圈蒙脸主垫图策略。
- 不修改模型选择、思考强度、并行调度、断点、结果保存、Provider 适配或专属 Chrome 登录资料。

## 经验教训

- 旧版本为解决“附件不足”而增加原图，不代表后续更严格的隐私边界仍应保留双主图；附件职责必须以当前产品规则为准。
- 文件名、manifest、操作说明和 Provider 输入框文案必须从同一个附件策略出发，否则 UI 看似正确时，后台仍可能发送额外文件。
- 一键蒙脸既然是隐私和授权边界，就必须是发送前硬门禁，不能只作为可选画布效果。
- 真实安装版与解包程序共享 Windows 单实例身份；打包验证前要先确认并关闭已安装实例，否则隔离启动可能被现有实例接管。
