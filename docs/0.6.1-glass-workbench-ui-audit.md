# 0.6.1 玻璃工作台 UI/UX 审计与画布滚轮修复

## 基线结论

现有三栏工作流与业务顺序是合理的，不需要为了视觉效果迁移核心功能。主要问题来自多代样式叠加、画布滚轮事件归属、主题语义不完整，以及窄窗口规则隐藏了核心操作。

## P0

### 画布滚轮同时滚动左栏

- 现象：指针位于原图画布并使用滚轮缩放时，左侧整栏也会向上或向下移动。
- 根因：画布使用 React 合成 `wheel` 事件。浏览器根事件和嵌套滚动容器仍可能继续处理滚轮，父栏没有形成明确的滚动边界。
- 解决：改为原生非被动 `wheel` 监听器，调用 `preventDefault()` 与 `stopPropagation()`；统一处理像素、行和页三种 `deltaMode`，限制异常滚轮增量并保留以指针为中心的缩放。
- 验证：Playwright 实际滚轮后缩放值改变，`.left-stack.scrollTop` 保持为 0。
- 经验：画布类生产工具必须明确拥有指针事件，不能只依赖合成事件的默认阻止行为。

## P1

### 主画布视觉优先级不足

- 现象：多层边框、彩色顶部线、阴影和卡片嵌套让三个栏位争夺注意力。
- 根因：`globals.css`、`levitated-workbench.css` 和 `hallmark-workbench.css` 保留了多个时期的视觉策略。
- 解决：新增最后加载的 `glass-workbench.css`，统一为实色内容面、克制玻璃外壳、单一紫色交互强调和红色选区语义；原图理解改为分割线式连续区段。
- 验证：1440、1920 和 2560 宽度下画布列至少占工作区 40%，普通内容不再依靠彩色阴影分组。

### 浅色与系统主题不完整

- 现象：设置为“跟随系统”时没有实时解析系统主题；后加载样式仍使用深色语义值。
- 根因：根节点只写入 `data-theme="system"`，没有监听 `prefers-color-scheme`。
- 解决：解析并监听系统颜色方案；在 `tokens.css` 中分别调校深浅色语义变量，图片画布在浅色外壳中仍保持中性深色。
- 验证：设置界面切换浅色后根节点为 `data-theme="light"`，语义背景为 `#ECEFF3`，无横向溢出和控制台错误。

### 窄窗口隐藏核心按钮

- 现象：1280px 以下保存、导入、导出和示例项目入口被旧媒体查询隐藏。
- 根因：旧规则通过 `display: none` 腾出顶栏空间。
- 解决：所有九个顶栏操作始终保留；窄窗口只压缩成 34px Lucide 图标按钮，并补充 `aria-label` 与原生 tooltip。
- 验证：1024、1280 宽度下九个按钮全部可见并拥有可访问名称。

### 辅助面板无法释放画布空间

- 现象：用户在精修主图时仍必须保留原图理解和制作流程两栏。
- 解决：新增两枚布局按钮，可独立收起原图理解和制作流程；组件保持挂载，展开后状态不丢失。
- 验证：两栏收起后画布宽度增长超过 40%。

## P2

- 后续可在独立版本中逐步合并三份历史样式文件，当前为避免大范围回归保留旧文件并使用明确的最终覆盖层。
- 可把原生 `title` tooltip 升级为统一延迟、可键盘触发的 Tooltip 组件，但不值得为此引入 Radix 或完整 shadcn 运行时。
- 历史和归档在结果数量很大时可增加虚拟化；当前数据规模未证明需要引入额外复杂度。

## Skill 的实际作用

- `ui-ux-pro-max`：确定 Operate 模式、三栏工作台、密度 8、动效 4、变化度 4，并拒绝其自动搜索结果中的粉紫渐变与 Bento 倾向。
- `impeccable`：用于第二轮层级和审美批评，移除彗星背景、彩色顶部线、过强阴影与卡片嵌套。
- `design-taste-frontend`：约束视觉焦点、控件比例、桌面信息密度和原创性。
- `web-design-guidelines`：落实跳转链接、可访问名称、焦点环、状态播报、滚动边界和窄窗口可用性。
- `design-md`：将产品事实、语义 token、材质、组件、动效和响应式规则固化到 `PRODUCT.md` 与 `design.md`。
- `awesome-design-md`：吸收 Apple 的内容优先，以及 Figma、Linear、Raycast 的高密度工具表面原则，不复制品牌外观。
- `shadcn`：审查组件语义与状态覆盖；项目没有 Tailwind/Radix，因此不安装运行时，继续复用现有 React 组件和 Lucide。
