# 耀创工坊 0.5.1 ChatGPT 恢复加固记录

## 现象

- 自动做图停在“正在后台重新载入 ChatGPT”，即使专属 Chrome 实际已经登录且输入框可见。
- 弱网或 ChatGPT 接口响应异常后，附件上传脚本可能连续出现 4 秒左右的页面执行超时。
- 屏幕外窗口恢复测试偶尔在原生显示操作仍未完成时提前判定失败。

## 根因

1. 输入框探测同时请求 `/api/auth/session`。该请求没有页面内部截止时间，网络请求挂起时，外层超时只能停止等待，不能取消仍在 Chrome `Runtime.evaluate` 中运行的请求。
2. 自动做图只需要确认输入框和登录页面结构，却被非必要的会话网络探测阻塞。
3. ChatGPT 新版中文输入框使用“问问 ChatGPT”等文案，旧规则覆盖不完整。
4. 对话 API、文本稿 API 和生成图片读取也存在同类的“外层超时但页面请求未取消”风险。
5. 原生窗口测试使用固定等待时间，没有等待 `waitForVisibility()` 返回，可能在 PowerShell 显示任务尚未完成时读取窗口位置。
6. 自动化生命周期结束后，渲染层可能保留最后一条临时恢复警告，造成任务已结束但界面仍像在恢复。

## 解决方式

- 将自动做图的输入框检查改为纯 DOM 探测；“检查登录”仍保留会话探测。
- 会话探测加入 `AbortController`、1.8 秒内部超时和短时缓存，网络异常不再占住页面执行通道。
- 补充“问问 ChatGPT”“询问 ChatGPT”等中文输入框识别，并在明确不是登录页时接受主编辑区域。
- 对会话 JSON、文本稿 JSON、生成图片二进制和位图解码分别增加内部可取消截止时间。
- 图片位图转换结束后调用 `ImageBitmap.close()`，避免连续任务积累解码资源。
- 后台恢复开始和结束均写入诊断日志，记录结果、耗时、页面地址和窗口状态；恢复成功后明确返回正常状态。
- 自动化结束时清除非终态的临时警告，保留成功、失败、暂停和未完成结果。
- 窗口恢复验证改为等待真实原生可见性确认，并执行屏幕外恢复及 20 轮隐藏/显示循环。

## 经验教训

- Chrome 页面脚本的外层 Promise 超时不等于取消页面里的异步操作；关键网络请求必须在页面内部可取消。
- 输入框可用性和账号会话网络状态是两个健康维度，自动发送前不应让非必要的会话请求阻塞 DOM 就绪判断。
- 原生窗口操作是异步队列，测试必须等待完成信号，不能依赖固定睡眠时间。
- 第三方网页结构仍可能变化；必须继续依靠有界超时、结构化探测、有限恢复和脱敏日志，而不是无限刷新或坐标点击。
