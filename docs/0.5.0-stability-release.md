# 耀创工坊 0.5.0 稳定性发布记录

## 目标与范围

0.5.0 完整移除 0.4.x 中不可稳定使用的内置后期编辑器，恢复“生成成功后直接保存 JPG 并归档”的主流程；同时加固专属 Chrome 控制队列、登录检查、模型读取、AI 分析和 1/2/3 路并行自动做图。原图尺寸、红圈外保护、一键蒙脸、参考图、提示词草稿、断点续做、用户项目和专属 Chrome 登录资料保持兼容。

## 问题记录

| 现象 | 根因 | 解决方式 | 经验教训 |
| --- | --- | --- | --- |
| 后期工作区图片方向异常，滤镜效果也无法达到 Photoshop 级一致性 | 自研 Canvas/WebGL 管线不是 Photoshop 算法，且增加了方向、显存、Worker 和临时文件状态 | 删除后期工作区、滤镜、Worker、路由和专用 IPC，不保留不可兑现的功能入口 | 对专业图像算法不能用相似名称代替；无法可靠交付时应移出核心链路 |
| 开启后期处理后，生成结果先进入临时区，保存和断点判断变复杂 | 同一结果存在“已生成、已暂存、已导出”多套状态 | 恢复单一完成标准：JPG 原子写入并重新解码校验后，才归档并更新任务检查点 | 自动化完成状态必须只有一个可验证事实来源 |
| 旧版待处理图片可能随功能移除而失去入口 | 0.4.x 使用独立 manifest 和 `PostProcessing` 目录 | 新版启动时只读恢复有效 JPG 到普通结果归档；原文件、清单和目录始终保留 | 数据兼容优先于目录清理，迁移失败必须保留原件和恢复位置 |
| “查看窗口”可能被后台“检查登录”长时间排队 | 所有窗口控制共用串行队列 | 查看窗口改为同键单飞的即时可见性通道；恢复操作进行中仍保持串行 | 用户主动查看应快速反馈，但不能绕过破坏性恢复互斥 |
| 登录检查、模型菜单、窗口恢复和自动做图存在极窄页面竞态 | 原逻辑只等待队列空闲，没有原子占住自动化槽 | 在控制队列内原子取得 AI 分析/做图任务槽；等待已开始的查看操作；迟到控制只能走任务安全分支 | “等待空闲”不等于“获得所有权”，跨 IPC 状态必须用原子租约 |
| 控制队列超时后，迟到 Promise 可能继续执行 | Promise 超时不会自动取消底层排队操作 | 加入过期标记和槽位释放；超时后的迟到任务不能占住永久忙碌状态 | 每个超时都必须检查底层工作是否仍会继续 |
| 诊断日志没有统一的未来脱敏屏障 | 当前调用点虽不写 Cookie，但依赖调用者自律 | 写入前统一过滤敏感键、Bearer 值和 URL 查询参数，并限制深度、数组和字符串长度 | 诊断应默认安全，不能要求每个调用者重复记住脱敏规则 |
| 已删除的后期模块仍出现在第一次 0.5.0 验包结果中 | `tsc` 不会删除输出目录里的陈旧 JavaScript，electron-builder 又会完整打包 `dist-electron` | 每次构建前只清理项目根目录内的 `dist` 和 `dist-electron`，并加入路径边界保护 | 删除源码后必须从最终 ASAR 反向检查，不能只检查源码树 |

## 主要实现

### 直接结果保存

`ChatGPT 成功结果 -> Electron 解码 -> 方向/尺寸标准化 -> 96% JPG -> 临时文件写入 -> 重新解码校验 -> 原子改名 -> 最终文件复验 -> resultArchive -> 批量检查点`

- 统一输出手机可直接打开的 `.jpg` / `image/jpeg`。
- 强制保持主图原始像素宽高，透明区域使用白色背景。
- 文件头、文件尾、解码结果和像素尺寸均通过后才算任务完成。
- 单张本地保存最多重试三次，绝不因此重新发送已经成功的 ChatGPT 请求。

### 旧版结果恢复

- 只读取 `D:\Yaochuang-Workshop\AppData\PostProcessing\manifest.json` 或备份清单。
- 最多恢复 20 张、单图最多 160 MiB、清单最多 4 MiB。
- 拒绝绝对路径、路径穿越、符号链接和目录外真实路径。
- 恢复只读，不删除、不移动、不重命名任何旧版文件。
- 未通过校验时显示“打开恢复位置”，用户仍可手动取回。

### 专属 Chrome 与自动化

- Playwright 本地管道保持主通道，固定端口为后备。
- Chrome/Edge 使用不同持久化资料目录，只管理与该目录精确匹配的进程。
- “查看窗口”同键点击只执行一次，并可在后台检查登录期间快速显示。
- “检查登录”、恢复窗口、模型读取保持串行；任务运行时不会刷新、切页或打开模型菜单。
- AI 分析与生成通过原子任务槽互斥，不与登录/恢复操作抢页面。
- Google OAuth、验证码和人机验证保持人工边界，软件不自动点击。
- 并行通道保持独立 taskId、附件证据、提示词快照、回复基线、重试和结果路径。

## 残余风险

- ChatGPT 和 Google 是持续变化的第三方页面，DOM、账号策略、额度、VPN 和网络状态无法由软件保证。0.5.0 的策略是结构化探测、有限恢复、停止发送、可读提示和脱敏日志，而不是盲点坐标或无限等待。
- 没有使用真实付费额度执行大批量图片生成压力测试；发送、失败识别、断点和保存链通过故障注入及既有真实流程回归。
- 旧版待处理图片不会自动删除，因此 D 盘可能继续占用旧文件空间；这是为避免商业升级时误删用户成片的主动取舍。
- 安装包当前没有 Authenticode 商业代码签名。首次从网盘下载时 Windows SmartScreen 仍可能提示未知发布者；正式销售前应购买并配置可信代码签名证书。
