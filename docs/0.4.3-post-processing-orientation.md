# 耀创工坊 0.4.3 后期预览方向修复记录

## 发布范围

- 基线版本：`0.4.2`。
- 修复版本：`0.4.3`。
- 保持不变：原始 JPG、原图像素尺寸、后期参数、临时结果、导出规则、AI 自动化和专属 Chrome 登录资料。

## 现象

- 后期处理左侧缩略图方向正常，中间 GPU 预览却上下颠倒。
- CPU 兼容预览没有同样问题，因此故障只出现在 WebGL2 渲染路径。

## 根因

- 后期 Worker 直接把 `ImageBitmap` 上传为 WebGL 纹理。
- 旧实现依赖 `UNPACK_FLIP_Y_WEBGL` 处理 DOM 图片方向，但该状态对 `ImageBitmap` 的行为并不能作为跨路径方向约定。
- 同时，全屏三角形的纹理坐标仍采用 WebGL 原点方向，导致普通预览和经过帧缓冲的高斯模糊结果都上下翻转。

## 解决方式

- 在共用顶点着色器中明确把纹理 Y 坐标转换为图片的左上角原点方向。
- 移除对 `UNPACK_FLIP_Y_WEBGL` 的隐式依赖，让原图、普通 GPU 预览、模糊帧缓冲和最终 JPG 使用同一方向约定。
- 不读取或改写 EXIF 方向，也不旋转原始图片；修复只作用于后期渲染输出。

## 构建事件

- 现象：旧 `release` 目录在 electron-builder 将 `win-unpacked.tmp` 改名为 `win-unpacked` 时连续返回 `EPERM`。
- 根因：仍在运行的 Vite 开发服务器监听到了 `release/win-unpacked` 中的文件变化并触发页面重载，正好占用了 electron-builder 即将原子改名的目录；源码构建、应用解包内容和安装器配置本身均无错误。
- 解决：核对目录后把失败产物移入同一发布目录的隔离名称，并在新的 D 盘版本目录完成正式打包。
- 经验：正式打包前先停止开发服务器，并使用版本隔离输出目录，避免文件监听器阻断原子目录替换。

## Photoshop 功能来源说明

- 当前 Camera 滤镜、颗粒、纹理、清晰度、晕影、扭曲度、添加杂色和高斯模糊均为耀创工坊独立的 WebGL/Canvas 实现。
- 它们借鉴常见摄影后期概念，但没有使用、复制或移植 Adobe Photoshop 源码，也不应宣称与 Photoshop 像素级相同。
- Adobe 的颗粒还包含大小和粗糙度；后期晕影包含样式、中点、圆度、羽化和高光等参数。现有简化控件与 Photoshop 参数面并不等价。
- 若商业需求要求与 Photoshop 完全一致，只能调用已安装并授权的 Photoshop，或接入 Adobe 官方 Photoshop API；这会增加 Adobe 授权、安装依赖、版本兼容或云端费用，必须作为单独功能决策实施。

## 经验教训

- 缩略图正确不能证明 GPU 处理链方向正确；必须用不对称像素哨兵验证。
- WebGL 图片源、帧缓冲和 Canvas/JPG 输出必须建立一套显式坐标约定，不能依赖浏览器对隐式翻转状态的差异行为。
- 使用相同功能名称不代表算法相同。商业界面必须区分“独立近似实现”和“实际调用原厂引擎”。
