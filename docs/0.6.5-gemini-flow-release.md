# 0.6.5 Gemini 自动化对齐与正式安装包发布

日期：2026-08-09

## 发布范围

- 将 `0.6.4` 安装包之后完成的 Gemini 自动化热修复正式升版为 `0.6.5`。
- 保留 ChatGPT 已验证的上传、模型确认、发送接受、完整回复读取、结果保存和断点续做流程。
- 不修改 Provider IPC、项目保存格式、专属 Chrome 登录目录或既有用户数据。
- 本轮只生成和验证安装包，不安装、不提交。

## 现象

1. Gemini 能打开模型菜单并选择模型，但附件上传后无法可靠点击发送按钮。
2. Gemini 偶尔只回填部分分析文本，不能稳定得到完整五字段 JSON。
3. Gemini 做图返回的结果可能使用 `blob:` URL，旧保存路径无法直接下载，自动流程停在结果保存之前。
4. ChatGPT 已成功切换到 `GPT-5.5` 时，输入区简写仍可能被判为“指定模型不可用”，导致附件上传前停止。

## 根因

- Gemini 页面已切换到新的 `send-button-container`、顶层消息和双回复结构，旧选择器与嵌套消息计数不再代表真实发送状态。
- 仅有文件输入事件不能证明附件已进入当前会话；发送按钮点击也不能单独证明消息被页面接受。
- 回复候选曾混入用户回显、合并祖先和旧消息，导致不完整内容被提前选中。
- Electron 主进程不能直接请求页面内存中的 `blob:` URL，需要在已登录页面上下文读取原始字节。
- ChatGPT 模型标签存在输入区简写、完整菜单名和父级值三种表现，旧比较规则过于严格。

## 解决方式

- Gemini 附件改为逐张上传并等待真实预览稳定，要求上传证据覆盖全部请求附件。
- 发送优先使用页面按钮，失败时使用专属 Chrome CDP 可信鼠标通道；发送后仍要求新顶层消息、会话 URL 或生成状态等可观测证据。
- 只在原始输入仍完整保留且没有发送接受证据时进行一次安全重试。
- 分析回复按发送前基线读取新模型消息，过滤用户回显、旧回复和合并祖先；五个核心字段完整后才回填。
- 生成结果以发送前图片基线选择新增图片；对 `blob:` 结果在页面上下文读取原始字节，再交给既有原尺寸保存和断点记录路径。
- ChatGPT 模型策略统一识别输入区简写和完整模型标签，指定模型仍必须在上传前得到确认，禁止静默降级。

## 经验教训

- 浏览器自动化必须验证“页面接受了操作”，不能把文件输入事件或按钮点击本身当作成功。
- 模型回复选择必须建立在发送前基线之上，并优先结构完整的新回复。
- 网页结果可能只存在于页面内存；保存层需要覆盖 `blob:`，同时继续执行尺寸和原子落盘校验。
- 每次正式打包前必须重新升版、跑回归并核对 ASAR，不能把后续热修复误认为已进入旧安装包。
- 清理交付目录时只处理安装包产物，不触碰源码、历史维护文档和用户数据。
