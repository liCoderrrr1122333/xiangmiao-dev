# 像锚

一个从品质车生活业务里长出来的 AI 图片生产工作台。

我叫李佳康，之前在品质车生活业务里做 AI Agent 架构和落地。隐形车衣、改色、轻度改装往往客单价高、决策慢，车主会反复问“装在我的车上是什么样”“颜色会不会失真”“能不能保留原车环境”。线上内容要把人带到咨询、预约和到店，图片既要吸引人，也要经得起销售、施工和车主的核对。

2025 年，我在做车主案例、营销内容和顾问系统时，开始持续关注一个断点：业务知道要表达什么，素材和参考图也有，但把要求交给通用 AI 做图后，人物、衣服、车或环境经常被一起改掉；返工靠聊天记录，人换了经验就丢了。这个阶段主要是业务观察、流程拆解和能力积累。2026 年 7 月离职后，我把问题收束成独立桌面软件，集中补齐从素材约束到生成、失败恢复和结果归档的链路。当前仓库可核验的产品实现与版本记录主要从 2026 年下半年开始，不能把 2025 年的业务探索说成已经发布的软件版本。

软件现在解决的是 **“把一次 AI 做图变成可检查、可恢复、可复盘的生产任务”**：导入原图和参考图，圈定允许编辑的区域，整理原图理解和提示词，选择网页或自配 API 生成，保存结果、评分、备注并再次修正。它面向获授权的人像及相关视觉素材编辑；使用者需要确认素材授权。

## 为什么与美团方向相关

我关注的是本地生活链路：**内容触达 → 用户产生具体问题 → 在线咨询 → 预约到店 → 线下履约 → 真实案例回流**。在品质车生活里，可信的案例内容能帮助车主更具体地表达需求，也能让顾问更早发现车型、颜色、预算和施工边界。像锚目前只覆盖其中的视觉内容生产与结果复盘环节，尚未接入交易、门店排期或履约系统。它的价值要由后续咨询质量、到店转化、返工率和审核通过率来验证，不能拿生成张数替代业务结果。

## 当前能做什么

- **约束素材**：导入主图、人脸及穿搭参考图；用红圈明确编辑区域；可选遮挡人脸，并保护原图尺寸和画幅。
- **组织意图**：分析场景、姿态、面部朝向和光影，生成可人工微调的提示词；素材改变时使旧提示词失效。
- **执行任务**：支持 ChatGPT 网页与用户自配的图片 API；批量任务记录发送状态，保存已完成结果，从缺失任务继续。网页验证由人处理，付费请求状态不明时不盲目重发。
- **接住结果**：自动保存或手动归档图片，记录评分与备注，生成二次修正提示词；可对结果做独立的相机质感处理，不覆盖原件。

这形成了当前可用的**人工参与闭环**：需求与素材 → 约束与提示词 → 生成 → 校验和归档 → 人工反馈 → 下一轮修正。它还不是自动学习、自动微调或能自主决定业务策略的系统。

## 下一步：受控的 AI 自进化

我希望把工作中做过的“案例清洗、RAG 检索、Agent 编排、评测与灰度回流”用于这个产品，但顺序必须是：**人审核案例 → 脱敏和标注 → 按场景检索相似案例 → 生成策略候选 → 离线评测 → 小流量验证 → 人批准发布或回滚**。当下结果归档和评分只是这个方向的数据入口，不等于训练闭环已经上线。有关优先级、数据边界、评测指标和阶段划分，见 [项目故事与面试说明](docs/项目故事与面试说明.md)。

## 技术与运行

Electron + React + TypeScript + Vite 构成桌面工作台；主进程负责文件、浏览器和 API 调度，界面负责素材、任务状态与结果复盘。Node.js 需要 `24.14.0` 或更新的 24.x。

```bash
npm ci
npm run dev
```

当前源码版本为 `1.2.4`。开发和源码分享先读 [开发说明](docs/DEVELOPMENT.md)，历史实现和验收边界见 [维护记录](docs/MAINTENANCE_HANDOFF.md)。首次使用默认展示自由 API 出图与本地 Ollama 分析，实际使用前需自行配置服务；也可改选 ChatGPT 网页路线。Gemini 网页通道保留适配代码，但当前界面入口不可选；macOS 构建、签名和公证不能仅凭源码配置视为已发布。
模块关系见 [架构总览](docs/架构总览.md)。

项目使用 Electron、React、MediaPipe、Sharp、Playwright 等第三方组件；对应依赖和资源许可保留在仓库中。独立产品的工作流设计与实现不等于声称这些底层组件也是我编写的。

源码不内置服务商 API Key。用户在运行时自行配置，选择“记住本机”时由系统加密存储；`.local-data/` 是被 Git 忽略的本机测试数据目录，分享源码或截图时不要附带它。旧版产品名只保留在升级校验、旧数据目录识别和历史维护记录中。历史记录中的旧署名、机器路径和安装包名称是旧版本当时的记录，不代表当前作者署名或当前交付物，也不应被改写成未发生的历史。

## 运行教程

下面是在这台 Mac 上从源码把像锚跑起来，并完成第一次做图的步骤。当前源码版本是 `1.2.4`。不要把别人电脑上的 `node_modules`、`dist`、`dist-electron` 或 `.local-data` 拷过来，原生依赖和本机数据都不能跨机器共用。

### 1. 准备环境

在源码根目录打开终端，先确认 Node.js：

```bash
node -v
uname -m
```

Node.js 需要 `24.14.0` 或更新的 24.x。`uname -m` 为 `arm64` 是 Apple 芯片，`x86_64` 是 Intel；安装 Node 时要和本机芯片一致。还需要可用的 `npm`。做 ChatGPT 网页流程时再安装 Google Chrome；只用自由 API 做图时，不需要先装浏览器。

源码根目录就是包含 `package.json` 的这一层。路径里有中文也可以，不要先 `cd` 到子目录再执行命令。

### 2. 安装依赖

```bash
npm ci
```

`npm ci` 按 `package-lock.json` 安装，适合第一次拿到源码。装完后如果终端提示 Electron 没有下载成功，在同一目录再执行一次：

```bash
node node_modules/electron/install.js
```

装好后应能看到 `node_modules/electron/dist/Electron.app`。

### 3. 启动

```bash
npm run dev
```

这条命令会先完整构建，再启动本地页面和桌面窗口，所以第一次会等一会儿，不是卡住。构建过程中就会打印一次：

```text
Local: http://127.0.0.1:5173/
```

这一行只说明页面构建完了，窗口还没出来。要等 Electron 进程起来，程序坞里出现名为 Electron 的图标，屏幕上才是像锚的窗口。窗口标题是「像锚」，程序坞名字仍是 Electron，因为开发模式用的是 Electron 本体，不是打包后的应用。这个地址只给窗口内部加载页面，不需要自己用浏览器打开。窗口出现后，终端要保持开着；关掉终端，应用会一起退出。

如果当前环境把 `ELECTRON_RUN_AS_NODE` 设成了 `1`，Electron 会被当成普通 Node 启动，并在 `import { nativeImage } from 'electron'` 一类语句上报错。改用：

```bash
env -u ELECTRON_RUN_AS_NODE npm run dev
```

`5173` 端口被占用时，开发服务会直接退出，不会去连别的项目页面。先停掉占用该端口的进程，再重新执行启动命令。

不需要热更新时，也可以构建一次后直接开窗口：

```bash
npm run build
npm start
```

改界面后，开发模式会热更新。改了 `src/main/` 或 `src/preload/` 后，热更新不会生效，需要在终端按 `Ctrl+C` 停掉，再执行一次 `npm run dev`。

### 4. 第一次打开时做什么

首次进入会看到「使用前必看｜先选择制作路线」。看完后点「我已确认，进入像锚」。软件不会在启动时替你打开网页或调用付费接口。

然后按这个顺序做一张图：

1. 上传原图。支持 JPG、PNG、WebP、HEIC。
2. 在要替换的人脸上画红圈。没有红圈不能发送。
3. 上传人脸参考图，并把正脸设为主参考图。至少一张。参考图只负责身份和发型，皮肤纹理仍跟原图红圈里的脸。
4. 打开「制作通道」，确认分析和做图各自走哪一条。两条是分开的，改其中一条不会自动改掉另一条。
5. 需要把画面描述写进提示词时，先做原图分析，再点「一键生成提示词」。自由 API 默认不把原图理解写入提示词，要在「原图理解」里打开。
6. 主图、红圈、参考图和提示词都齐了，按钮会变成「开始做图」。生成结果会归档，原图不会被覆盖。

### 5. 分析和做图怎么配

分析来源在「制作通道」里选：

- **豆包**：默认分析来源，域名已内置。设置里不能手填 Key，软件读取本机已经加密保存的密钥。新电脑上如果还没有这份密钥，分析会提示「豆包分析密钥尚未保存在本机」。这时改用下面的本地模型或 ChatGPT 分析即可。
- **本地模型**：连接 `http://127.0.0.1:11434`。制作通道里显示未就绪时，按提示安装或下载模型，状态变成「本地模型已就绪」后再分析。
- **ChatGPT**：用像锚专属 Chrome 里已登录的网页账号做分析。登录和验证码由人完成。
- **Gemini**：界面按钮当前不可选。

做图通道同样在「制作通道」里选：

- **API**：用你自己的图片接口。点「配置 API」，填写服务地址和 Key。模型要填该服务真实提供的图片模型，聊天模型不能拿来做图。勾选记住后，Key 会加密存在本机 `.local-data/`，不会写进源码。配置成功后按钮显示「API 已配置」。
- **ChatGPT**：走网页自动化。先在设置里检查登录。全自动发送时才能使用 1 路、2 路、3 路；路数只决定同时做几张，不改变单张画质。
- **Gemini**：界面按钮当前不可选。

源码里没有预置任何服务商 Key。`.local-data/` 已被 Git 忽略，里面有设置、自动保存、加密密钥和浏览器资料。分享源码或截图时不要带上这个目录。

### 6. 退出

在运行 `npm run dev` 的终端按 `Ctrl+C`。下次还是在源码根目录执行 `npm run dev`。本机设置会留在 `.local-data/`，不会因为退出而丢失。

不要只点窗口关闭按钮就认为进程没了。设置里的「长期保留网页登录」默认是开的，点关闭会把窗口收进托盘，`5173` 继续被占用。下次启动前，先在托盘退出像锚，或回到原来的终端按 `Ctrl+C`。

### 7. 这次启动踩过的坑

这些都是实际跑起来时遇到的，不是假设。

- **看到本地地址，屏幕上没有窗口。** `npm run dev` 里的 `vite build` 会先打印 `Local: http://127.0.0.1:5173/`，这时 Electron 还没启动。再等终端出现 Electron 进程。程序坞里找的是 Electron，不是「像锚」。
- **进程在、端口在听，就是没有窗口。** 启动时会去读 `.local-data/relay-api-key.pending.json`。这个待导入密钥文件本来就可以不存在，但旧代码没接住「文件不存在」，抛出 `UnhandledPromiseRejectionWarning` 之后，窗口创建被跳过，Electron 进程却还留着。现在缺这个文件不会再挡住窗口。如果终端仍刷这条报错并且没有窗口，说明跑的还是旧构建：在原终端 `Ctrl+C`，确认 `5173` 已释放，再执行一次 `npm run dev`。没有这份文件只表示自由 API 密钥还没导入，窗口可以开；要做图就在「配置 API」里重新填。
- **`nativeImage` 导出不存在。** 报错是 `The requested module 'electron' does not provide an export named 'nativeImage'`。原因是环境变量 `ELECTRON_RUN_AS_NODE=1`，Electron 被当成普通 Node 启动了。改用 `env -u ELECTRON_RUN_AS_NODE npm run dev`。
- **`5173` 已被占用。** 上一次开发进程没退出，常见于窗口收进了托盘。先停掉旧进程再启动。开发服务不会改去连别的项目页面。
- **`npm ci` 之后没有 Electron.app。** 安装脚本被跳过时，二进制不会下载。在源码根目录再执行 `node node_modules/electron/install.js`，直到能看到 `node_modules/electron/dist/Electron.app`。不要拿 Windows 上的 `node_modules` 来用。
- **终端里 `spawn ollama ENOENT`。** 本机没有安装 Ollama。这不影响窗口打开，只说明本地模型分析还不能用。要用这条分析，先安装 Ollama，再在制作通道里等「本地模型已就绪」。
- **豆包分析提示密钥尚未保存在本机。** 设置里不能手填豆包 Key，软件只读本机已经加密的密钥。没有这份密钥时，分析改用本地模型或 ChatGPT。
- **「开始做图」是灰的。** 看按钮上的提示。通常还缺原图、红圈、参考图或提示词。
- **自由 API 提示未配置或模型不存在。** 回到「配置 API」，确认地址、Key，以及模型名和该服务商列表里的图片模型一致。聊天模型不能拿来做图。
