# 0.6.9 ChatGPT 附件与原图分析热修复

更新时间：2026-08-12

## 现象

- ChatGPT 做图对话偶尔提示没有可用的原图和参考图附件，无法执行局部人脸编辑。
- 原图 AI 分析偶尔长时间停在“附件上传仍未完成或发送按钮不可用”，界面分析按钮在后台请求结束前持续不可用。
- 用户提供的现场截图显示，提示词已经进入 ChatGPT，但对话侧没有收到完成编辑所需的真实图片附件。

## 根因

1. 正式做图发送清单只有带红圈定位图和参考图，明确遗漏了无标记原图；导出清单中的自动化附件记录也同步遗漏。
2. 旧附件确认把 `input[type=file].files` 当作上传成功证据。它只能证明文件被注入网页控件，不能证明 ChatGPT 已接收并渲染附件预览。
3. 页面存在多个隐藏文件控件时，旧逻辑会在当前 composer 外选择评分最高的全局控件，文件因此进入无关入口，输入区没有附件回执。
4. 多附件一次性注入会受到当前 ChatGPT 文件控件生命周期影响；页面可能只处理最后一个文件，或在第一个附件尚未稳定时重建控件。
5. 菜单关闭和发送依赖脚本 `.click()`；当前网页在部分状态下只响应可信输入事件，导致发送按钮可见但动作没有被页面接受。

## 解决方式

- 正式做图附件顺序调整为：无标记原图、红圈定位图、人脸参考图、衣物配饰参考图；导出 manifest 与操作说明同步更新。
- 多附件改为逐张上传，每张都等待独立附件预览稳定四轮且上传进度消失后，再处理下一张。
- 文件控件只允许命中当前 ChatGPT composer 内部；页面外围隐藏控件一律拒绝，立即切换经真实页面验证的 CDP 拖放通道。
- `fileInputCount` 不再参与成功判定；成功必须来自文件名、顶层附件预览或移除附件控件等可见回执。
- 大图仍在上传时继续等待，不重复注入；没有任何附件回执时尽早切换拖放，减少分析按钮无效等待。
- 发送前再次核对全部附件、提示词、上传进度和发送按钮；菜单关闭与发送使用可信 CDP 键盘/鼠标事件，并保留一次有证据约束的安全重试。
- 新增真实 ChatGPT 附件验证和真实 AI 分析回填验证脚本，全部使用 D 盘隔离登录资料副本，不修改正式项目与正式 Chrome 登录资料。

## 经验教训

- 浏览器文件控件里的 `files` 不是服务端接收证据，自动化必须等待用户可见的附件回执。
- 动态网页上的全局隐藏控件不能按“看起来像图片上传”猜测用途；找不到当前输入区所有权时应切换可验证的后备通道。
- 多附件工作流应逐项建立稳定检查点，避免一个控件重建或慢上传让整批素材处于不可证明的中间状态。
- UI 按钮持续禁用常常是后台状态机没有结束的表象；修复应落在真实阻塞边界，而不是增加前端强制解锁或缩短总等待时间。
