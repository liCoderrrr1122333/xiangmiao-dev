# 耀创工坊 1.1.2 ChatGPT 自适应批量自动化

更新时间：2026-08-16

> 2026-08-21 未发布修订：当前源码已将工作模式调整为“跟随网页当前模型，只设置思考强度”，并加入固定冷却截止时间、12/20/30 秒提交节奏、60 秒无进展提前停止、3 分钟硬截止和单通道待确认隔离。正式发布历史仍按本文记录，修订详情见 `docs/unreleased-chatgpt-automation-speed-and-protection.md`。

## 问题现象

- 长批次会反复打开模型菜单并重新确认思考强度，产生与任务内容无关的网页操作。
- 三路并行虽然已经串行化附件上传和发送，但固定提交节奏无法根据最近页面响应、失败率和服务端限制自动减速。
- 页面出现“请求过于频繁”时，旧流程可能先进入发送结果不确定分支，五分钟零点击冷却和自动恢复无法稳定接管。
- 旧断点只记录完成任务，不能完整表达等待、处理中、成功、失败、暂停和运行耗时，界面也缺少长批次监控。

## 真实根因

1. 模型与思考强度仍被当作每个任务的步骤，而不是当前 ChatGPT 标签页可复用且需要验证的配置状态。
2. 提交间隔、最近任务表现和冷却截止时间没有形成可持久化的统一运行策略，重启后不能完整恢复节奏。
3. 限流文本分类晚于发送结果不确定判断，明确限流可能被更宽泛的错误分支提前截获。
4. 批次断点结构缺少逐任务生命周期及最近样本，无法为 100 张任务提供准确监控和恢复依据。
5. 回归验证另外发现：部分滑块不响应 `Home` 键，旧遍历会从“极高”继续向右，永远无法到达“高”。

## 解决方式

- 新增每个 ChatGPT 页面独立的已验证配置缓存。发送前先被动读取当前模型与思考强度；两者均符合目标时不打开菜单、不发送点击事件。用户主动显示自动化窗口后立即失效缓存，避免人工修改后的陈旧判断。
- 保留现有全局 UI 互斥边界：模型确认、附件注入、提示词填写和发送确认串行执行；发送被页面接受后释放互斥，已提交的 1/2/3 路继续并行等待和保存结果。
- 新增三种明确工作模式，均固定使用 GPT-5.5：快速为低、均衡为中、稳定高质为高。不得静默切换模型或降低思考强度。
- 批量上限提升到 100 张；断点升级为 v5，持久化逐任务状态、尝试次数、结果路径、错误、最近 10 个运行样本、冷却截止时间和休息计数。重启时将未完成的处理中任务恢复为等待，不重复已保存任务。
- 自适应提交间隔以 60 秒为安全下限；最近页面响应或失败率变差时提高到 90 秒或 120 秒；每完成 10 张自动休息 120 秒。
- 明确限流优先于发送不确定分类。检测到“请求过于频繁”等限制后立即停止新增网页操作、保存断点、降为单路并进入五分钟零点击冷却；冷却结束后只续做缺失任务。
- 运行监控新增当前任务、完成数、失败数、总耗时、平均耗时、当前节奏和恢复倒计时。
- 思考强度滑块仅在目标不匹配时操作；先用可验证的轨道位置定位，短滑块在 `Home` 无效时使用有限左移归零，再逐档验证。任何路径都必须读回准确目标强度才允许上传。
- 没有加入随机“真人行为”或规避限制的逻辑，也没有用无限重试、吞错和更长盲等掩盖根因。

## 关于输入 `/` 切换模型

截至本次维护，OpenAI 官方帮助文档仍把模型与思考强度描述为 model picker 中的用户设置，没有提供可供 ChatGPT 网页自动化依赖的 `/` 模型切换协议。把 `/` 写入真实 composer 还存在失败后污染图片提示词的风险，因此 1.1.2 不接入该路径，继续使用可读取、可验证、失败即停的 model picker 流程。

## 验证边界与残余风险

- 本轮完成了单元测试、页面夹具、隔离 Electron 与正式打包程序验证。首次安装状态下没有正式 AppData 和登录资料，因此没有冒充真实 ChatGPT/Gemini 账号完成 100 张在线实发。
- ChatGPT 与 Gemini 网页 DOM、账号额度、地区、网络和服务端限制仍可能变化。软件会保留首个真实原因、断点和冷却状态，但不能保证外部服务永不触发限流。
- 100 张表示队列、断点和监控的支持上限，不代表通过高频请求绕过服务端限制；实际吞吐由页面状态和服务端响应决定。
- 安装器没有商业代码签名证书，Windows 可能显示未知发布者提示。

## 经验教训

- 模型和思考强度属于网页会话配置，应采用“读取、比较、必要时修改、再次验证”，不能成为每张图的固定点击步骤。
- 对明确限流应优先分类并保持零点击冷却；错误分类顺序与重试次数同样重要。
- 断点续做不仅要保存完成编号，还要保存任务生命周期、节奏样本和冷却截止时间，才能在重启后保持同一行为边界。
- 所有点击优化都不能削弱发送前门禁。少点击的前提是已有可靠状态证据，而不是假定网页保持不变。
