# 耀创工坊 1.2.1 本地分析与制作通道优化

日期：2026-08-24

## 问题现象

- 豆包网页分析长期停在输入区清理或页面恢复阶段，导致 API 做图前的 AI 分析和网感姿势不可用。
- 制作通道长期展开，占用原图理解栏空间；API 配置在制作通道和运行区重复出现。
- 并行选择左侧存在无意义空白，结果归档操作拥挤，入口层级不清楚。

## 根因

- 豆包网页依赖第三方网页 DOM、登录和窗口状态，稳定性与 API 做图链路无关，却成为分析前置阻塞点。
- Provider、分析来源和运行参数分散在多个区域，同一配置被重复展示。
- 原布局沿用窄列按钮尺寸，没有让并行和结果操作根据右栏宽度重新分配空间。

## 解决方式

- 删除豆包网页窗口、上传、发送、结果读取和控制队列残留，以现有 Ollama 视觉模型作为本地 AI 分析与网感姿势来源。
- 新增本地模型状态检测、官方安装入口、`qwen2.5vl:3b` 下载进度和失败说明；已安装视觉模型会直接复用。
- AI 分析和网感姿势分别走本地 Ollama IPC，网感姿势仍要求返回恰好 8 条中文结构化结果。
- 制作通道改成可收起摘要栏，明确“分析来源 -> 最终做图”组合；API 只在这里配置。
- 并行通道改成整行等宽 `1 路 / 2 路 / 3 路`，运行区只保留脱敏 API 状态。
- 结果归档改成一行三入口：批量降 AI 感、批量面部自然化和紧凑的全部结果入口。
- UI 动效只使用 160ms 的 transform 过渡和轻微按压反馈，保留精确指针 hover 与 reduced-motion 支持。

## 经验与残余风险

- 本地分析应以能力检测为准，不再用不稳定网页充当 API 做图前置依赖。
- 首次使用本地分析仍需要用户安装 Ollama 并下载视觉模型；模型体积、下载时间和推理速度取决于机器配置。
- API 做图通过本地夹具、密钥隔离、图像保真和打包启动验证；本轮没有使用真实用户 Key 发起计费生成。
- Gemini 仍保持灰显，等待后续完成正式适配后再开放。
