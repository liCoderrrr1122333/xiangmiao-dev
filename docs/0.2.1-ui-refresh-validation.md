# UI Refresh Validation

## 2026-07-31: Development shell cache permission

- Symptom: `npm run dev` started Vite successfully, then Electron reported disk-cache creation failures and could not load `http://127.0.0.1:5173`.
- Root cause: the current local verification session did not have write access to Electron's default Chromium cache directory. This happened before application renderer startup and is unrelated to the workbench UI or ChatGPT automation code.
- Resolution: validated the renderer through a standalone Vite process on `127.0.0.1:5173`, with a real headed browser at 1280x720. Production build and the complete automated regression suite passed.
- Lesson: distinguish host cache-directory permissions from renderer failures. Do not change the dedicated Chrome profile, login persistence, or application data paths to work around a developer-shell cache restriction.

## UI refresh coverage

- The selected direction uses the precision dark workbench as the primary structure and a larger media canvas with continuous reference strips as the secondary influence.
- Verification covered the 1280x720 supported desktop viewport, production compilation, TypeScript, and all existing automated tests.

## 2026-07-31: Material cards displaced the primary canvas

- Symptom: after files were loaded, face and clothing reference cards exposed every tag, selector and note field at once. The left column became form-heavy and the original-image canvas lost first-screen priority.
- Root cause: the existing card layout was designed for a vertically stacked form, while the selected direction requires a compact, horizontally scannable material strip.
- Resolution: reference cards now keep the thumbnail and identity visible by default, with complete per-item editing inside an expandable detail region. Opening a card widens the active editing track and increases the strip height so no controls are clipped.
- Lesson: dense production controls should remain available without competing with the main canvas during normal scanning.

## 2026-07-31: Minimum desktop width clipped the third column

- Symptom: at 1280x720 the document reported no horizontal scrollbar, but fixed minimum column widths still pushed part of the right work area outside the visible layout.
- Root cause: a later desktop style overrode the established compact breakpoint with three fixed minimum tracks.
- Resolution: the final 1180-1380 breakpoint uses proportional `minmax(0, ...)` columns. At 1280x720 the three columns measure approximately 480/369/395 pixels and the right edge remains within the viewport.
- Lesson: overflow metrics alone are not sufficient when an application shell intentionally hides overflow; verify the bounding box of the last interactive column.

## 2026-07-31: Prompt controls delayed access to results

- Symptom: mode selection, export actions, guard labels and history made the prompt panel too tall, placing the result archive well below the primary action.
- Root cause: frequent and infrequent controls shared the same always-visible visual level.
- Resolution: the generated prompt, copy action and ChatGPT action remain immediate; mode, export, API and history tools are preserved in a disclosure. The result archive now follows the primary action in the first-screen hierarchy.
- Lesson: preserving functionality does not require every control to carry equal visual weight.

## 2026-07-31: Persistent panel instructions made the workspace feel cluttered

- Symptom: the original-image and reference-image headers repeated protection rules, reference semantics, file labels and setup guidance. The permanent copy competed with the actual canvas, materials and analysis fields.
- Root cause: onboarding guidance and operational state were placed in the always-visible panel hierarchy instead of contextual help and accessible labels.
- Resolution: the left workspace now keeps only the panel title, compact item count and direct actions. Empty states use one action label plus a short file or material hint; detailed meaning remains available through existing tooltips, button labels and ARIA descriptions.
- Lesson: a production workspace should keep persistent text to state and action. Instructions belong at the moment they are needed, not above every task.

## 2026-07-31: Original understanding header repeated analysis guidance

- Symptom: the center header showed a module label, five-part subtitle, analysis state, helper sentence and two protection tags before users reached the actual scene, pose, face-direction and lighting fields.
- Root cause: analysis onboarding, result state and the primary panel identity occupied the same permanent header.
- Resolution: the header now contains only `原图理解` and the existing `AI 分析` action. Runtime analysis feedback remains in the dedicated status region and all four editable analysis sections are unchanged.
- Lesson: show task identity in the header and transient system feedback beside the task that produced it.

## 2026-07-31: Authorization checkbox interrupted the primary workflow

- Symptom: a long authorization statement occupied permanent space below the analysis controls and added an extra checkbox before prompt generation or sending.
- Root cause: policy guidance was implemented as a required project-state gate inside the main production workflow.
- Resolution: the visible statement, checklist requirement, status-bar label and generation/API blocking checks were removed. Main image, red circle, reference image and prompt requirements remain unchanged; the legacy project field is retained for import compatibility.
- Lesson: legal or policy guidance should not become repeated workspace content unless the product explicitly requires a blocking acknowledgment.
