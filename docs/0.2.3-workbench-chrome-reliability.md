## 问题一：原图只能标圈，不能直接拖动画布

**现象**

主图上传后左键默认进入红圈绘制；放大后缺少符合图像软件习惯的平移操作。

**根因**

`MainImageCanvas` 只有绘制和移动红圈两种工具，缩放始终以画布中心处理，也没有独立视图偏移。

**解决方式**

- 新增默认 `pan` 工具、独立视图偏移和边界约束。
- 左键拖动画布，滚轮以鼠标位置为锚点缩放。
- 进入绘制或编辑红圈时只操作原图坐标，不触发画布平移。
- 上传新图和重置视图时恢复 100% 缩放与居中。
- 导出仍使用原图像素尺寸和原始红圈坐标，不受视图变换影响。

**经验教训**

画布视图状态必须与项目图像数据分离；缩放和平移不能写回原图尺寸或标注坐标。

## 问题二：核心操作顺序不符合工作流

**现象**

“打开 ChatGPT 做图”位于提示词区域之后，用户需要先向下寻找最终操作。

**根因**

主操作按钮和提示词生成按钮分属不同 DOM 区块。

**解决方式**

把“打开 ChatGPT 做图”移动到右侧操作组，并紧邻“一键生成提示词”正上方；保留原事件、禁用条件和自动化入口。

**经验教训**

工作流顺序应同时体现在视觉顺序和 DOM 顺序，避免仅用 CSS 排序造成键盘导航与视觉不一致。

## 问题三：查看窗口、检查登录偶发无响应或空白

**现象**

- 调试端口或遗留进程失效时，普通用户可能看到 `ECONNREFUSED`。
- 已存在多个页面时可能选择空白页或旧页面。
- Google OAuth 进行中被登录检查抢到前台。
- 自动恢复没有显式次数、原因和用户恢复入口。

**根因**

- 固定端口、页面选择和窗口显示逻辑之间缺少统一健康检查。
- 页面选择曾依赖首个页面或首个 CDP target。
- 检查登录的 OAuth 分支可能调用显示窗口。
- IPC 只提供查看和检查，没有独立的受控恢复动作。

**解决方式**

- Playwright 本地管道继续作为主通道，固定端口只作后备。
- 对 ChatGPT、OpenAI 登录和 Google OAuth 页面打分，拒绝优先选择 `about:blank`。
- 查看窗口前检查页面可用性；空白时先清缓存重载，再导航到 ChatGPT。
- 后台恢复最多两次并退避，超过上限返回可读原因和“恢复窗口”按钮。
- 新增恢复窗口 IPC；按钮操作有即时状态和超时。
- 检查登录不调用窗口显示或外部浏览器，不抢前台。
- Google OAuth 页面只监测状态，不自动点击“下一步”、验证码或人机验证。
- 诊断写入 `logs/chatgpt-automation.ndjson`，记录时间、版本、后端、浏览器、窗口状态、URL、失败原因和恢复结果。

**经验教训**

“浏览器进程存在”不等于页面可用；进程、传输、页面、窗口位置和登录状态必须分别检查，并向用户返回可执行的恢复动作。

## 问题四：侧脸蒙脸失败且错误提示被隐藏

**现象**

MediaPipe 人脸关键点在大角度侧脸上可能找不到稳定面部；精简桌面布局时隐藏了旧详情栏，也连带隐藏失败提示。

**根因**

- 蒙脸只有“关键点 + 语义分割”一条成功路径。
- 状态信息与调试性质的红圈尺寸信息共用同一容器。

**解决方式**

- 保留关键点路径作为高精度主路径。
- 关键点失败时增加语义分割降级：红圈仍为硬边界，只接受 face-skin 类别，排除头发、衣物、配饰和 body-skin。
- 设置最低像素数、种子数和覆盖率，避免无脸区域误遮挡。
- 加载与错误信息改为画布内短反馈，不占用布局，也不会静默失败。

**经验教训**

精简界面不能删除故障反馈；高精度模型需要受约束的降级路径，而不是用整个红圈粗暴填充。

## 问题五：1280×720 下画布工具被裁切

**现象**

三栏没有横向溢出，但低高度时单列画布工具栏的后半部分超出主图面板。

**根因**

工具栏高度按大窗口设计，左栏同时保留了参考图素材带，导致主图面板在 720 高度下压缩。

**解决方式**

仅在桌面宽度且高度不超过 760px 时改用四列紧凑工具栏；大窗口继续保持单列。所有 11 个工具均保持可见，页面无横向滚动。

**经验教训**

最低分辨率验收不能只检查页面滚动条，还要逐个验证关键控件的可见矩形是否处于所属面板内。

## 发布打包故障记录

**现象**

第一次执行 `electron-builder --win nsis` 时连接 GitHub `20.205.243.166:443` 超时；切换 Electron 镜像后，NSIS 工具下载仍继续尝试 GitHub。

**根因**

Electron 运行时与 `electron-builder` 的 NSIS/7zip 资源使用两套独立下载地址和缓存变量，只配置 `ELECTRON_MIRROR` 不会影响 NSIS。

**解决方式**

- `ELECTRON_CACHE=D:\Yaochuang-Workshop\BuildCache\Electron`
- `ELECTRON_BUILDER_CACHE=D:\Yaochuang-Workshop\BuildCache\electron-builder`
- `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`
- `ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/`

配置两类镜像后 Electron、NSIS、7zip 和 NSIS resources 均下载到 D 盘并完成打包。

**经验教训**

商业发布构建应同时固定 Electron 与打包器二进制缓存，避免 CI 或交付机器只因 GitHub 网络波动失败。
