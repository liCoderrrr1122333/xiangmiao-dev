# 0.6.7 可版本化首次启动公告

日期：2026-08-10

## 功能范围

- 在耀创工坊首次启动当前公告版本时显示强制确认的环境检查公告。
- 公告包含网络环境、AI 服务登录状态和优先使用 ChatGPT 三项提示。
- 只复用现有 `AppSettings`、Zustand 设置仓库和 `settings.json` IPC，不新增账号、联网记录、配置文件、IPC 或依赖。
- 不修改主工作台布局、项目格式、图像处理、网页自动化、并行任务、结果保存、断点、自动保存或专属 Chrome 用户资料。

## 需求现象

- 新用户进入工作台后可能在未准备网络节点或未登录 AI 服务的情况下直接操作，容易遇到页面打不开、跳转失败和生成流程不稳定。
- 当前版本以 ChatGPT 流程最稳定，需要在首次使用前给出克制、明确的优先推荐，同时仍保留 Gemini 入口。
- 公告只能确认一次，但后续公告内容更新时必须能够通过版本号重新向所有未确认新版公告的用户显示。

## 实现方式

- 新增 `CURRENT_NOTICE_VERSION = 1` 和公告版本归一化策略；无效、缺失或较旧的 `acknowledgedNoticeVersion` 均视为未读。
- `AppSettings` 新增 `acknowledgedNoticeVersion`，默认值为 `0`；确认后通过现有 `window.masklock.writeSettings` 保存当前公告版本。
- 设置读取完成前使用与应用背景一致的固定启动层，避免先显示可操作主界面再补弹窗，也避免已读用户短暂看到公告。
- 公告显示期间主应用根节点设置 `inert` 和 `aria-hidden`，业务快捷键不执行；公告位于主应用根节点之外，保持主工作台 DOM、网格和窗口尺寸不变。
- 启动登录检查和本地视觉模型预热在公告确认后才执行一次，防止外部窗口或登录流程抢在公告之前出现；项目与自动保存恢复仍沿用原流程。
- 确认按钮先写入完整设置，写入成功才关闭；写入失败保留公告、恢复按钮并显示“保存失败，请重试”。
- 公告不提供关闭、跳过或以后再说；Escape 和点击遮罩不能关闭，Tab 焦点固定在唯一确认按钮。

## UI 与无障碍

- 新增独立 `StartupNoticeModal` 和专属样式，复用现有颜色、字体、间距、阴影、圆角、主题及动态 token。
- 三个纵向信息区块使用现有 Lucide 图标；第三项仅用低饱和推荐标签和细边框强调，不使用警告色或营销式视觉。
- 深色首屏 modal 稳定尺寸为 `620 x 617` CSS 像素，主按钮高度 `44`；`1024 x 600` 浅色窗口内完整显示，无横向溢出。
- 支持深色、浅色、跟随系统、字体设置、`prefers-reduced-motion` 和应用内 reduced motion。
- 使用 `role="dialog"`、`aria-modal`、`aria-labelledby`、`aria-describedby`、初始按钮焦点和写入失败 `role="alert"`。
- 视觉对比记录：`design-qa.md`，最终结果为 `passed`。

## 经验教训

- 首次启动门禁必须使用三态水合，不能用默认值先猜未读状态，否则已读用户会看到瞬时弹窗。
- 保存完整设置的异步写入必须串行；先关闭再保存会造成失败后仍被误判为已读，初始化写入与确认写入并行也可能覆盖新版本号。
- 强制公告不能复用带关闭按钮和 Escape 行为的普通设置弹窗，视觉复用和交互语义应分开。
- 原有 Electron 测试必须等待公告真实出现后再确认，不能用瞬时 `isVisible` 推断异步设置水合已完成。
- 视觉效果图可以确定方向，但真实实现仍应优先遵守已写明的 620px 尺寸、主题 token 和键盘可访问性约束。

## 残余风险

- 后续修改公告内容时必须同步提升 `CURRENT_NOTICE_VERSION`，否则已确认用户不会再次看到。
- 如果 `settings.json` 因权限或磁盘问题无法写入，公告会按设计保留并要求重试；程序不会把失败静默当成已读。
- 当前 `0.6.7` 已封装并完成离线内容检查与 Defender 扫描，但尚未执行真实升级安装和安装后账号流程复测；该步骤保留给 Hale 手动验收。
- 当前系统没有安装 7-Zip，因此未增加第三方 NSIS 外部解压测试；Electron Builder 的原生 `win-unpacked` 产物和 `app.asar` 已完成版本与内容核对。
