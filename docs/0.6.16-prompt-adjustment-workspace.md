# 耀创工坊 0.6.16 提示词微调工作区

日期：2026-08-14

## 问题现象

- 右栏原有“提示词选项与导出”入口颜色和层级过弱，很多使用者没有发现提示词可以继续编辑。
- 展开后直接在狭窄右栏内编辑，长提示词可见范围太小，难以通读和精确修改。
- 提示词微调必须发生在“一键生成提示词”之后，不能用空白编辑器代替现有生成流程，也不能在取消时污染已经生成的草稿。

## 根因

- 可编辑能力与复制、导出等次级操作收在同一个低对比度折叠标题中，没有独立的进入命令和明确状态。
- 编辑器受右栏宽度限制，长文本只能在很小的区域内滚动，编辑任务与预览任务没有分开。
- 原组件直接复用当前提示词文本，没有事务式草稿边界；如果把编辑器简单放大，关闭与保存的语义仍不够清楚。

## 解决方式

- 在已有提示词预览下增加常驻的“提示词自定义微调”入口，使用克制的金色双线、四角几何纹样和“进入微调”按钮提高可发现性。
- 金色只用于这个发现入口、微调弹窗边框与保存命令，不改变全局紫色主操作、红圈和任务状态的既有语义。
- 只有存在已一键生成的提示词时才启用入口；打开弹窗时复制当前 `promptText` 作为临时草稿，保证微调基于现有结果。
- 弹窗采用居中的大尺寸稳定实色编辑区，并提供标题、关闭、取消和保存；点击取消、关闭、遮罩或按 `Escape` 均不写回，只有“保存修改”才更新提示词并标记为自定义。
- 保留原有提示词预览、复制、生成模式、重新生成、导出和 API 操作，将其整理到“生成与导出选项”，不删除正式功能。
- 弹窗增加焦点陷阱、关闭后焦点恢复、正文滚动锁定及可访问名称；动效只使用 `transform` 与 `opacity`，并继续支持 reduced motion、reduced transparency 和 contrast 偏好。

## 经验教训

- “功能存在”不等于“用户能发现”；高价值但低频的入口需要清楚名称、独立命令和适度的视觉辨识度。
- 长文本预览和长文本编辑是两种任务。右栏适合快速核对，真正修改需要足够宽高且不改变主工作台布局的临时工作区。
- 微调必须以已生成提示词为输入，并采用“打开复制、保存提交、取消丢弃”的事务边界，才能避免误改和空白覆盖。
- 装饰需要服务于发现性。金色纹样只围绕单一入口使用，不能演变为全局主题、发光效果或新的卡片层级。
