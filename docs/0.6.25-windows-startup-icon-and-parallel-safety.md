# 0.6.25 Windows 启动兼容、新图标与三路提交保护

日期：2026-08-15

## 问题现象

1. 用户电脑直接启动正式安装版时，Electron 加载 `resources/app.asar/dist/index.html` 报 `ERR_FAILED (-2)`，同时 GPU sandbox 崩溃；把 `app.asar` 解包为 `resources/app` 并使用 `--disable-gpu-sandbox` 后可以启动。
2. 应用、安装器和快捷方式仍使用旧图标，需要统一替换为 Hale 提供的紫黑镜头角色图。
3. 0.6.24 三路批量虽然已串行提交，但页面没有确认一次发送时仍会自动补点；批次随后还会重试这个已经点击过的任务，继续增加访问频率。

## 真实根因与证据

### Windows 启动

- 当前维护机上的 0.6.24 ASAR 安装版能够启动，因此这不是所有电脑都会出现的代码错误。
- 用户现场给出的可复核差异是：`app.asar + GPU sandbox` 失败，而 `resources/app + --disable-gpu-sandbox` 成功。这说明受影响环境同时存在 ASAR 读取兼容和 GPU 进程沙箱兼容问题。
- 继续只发布 ASAR 包无法覆盖已经出现的机器差异；全局 `--no-sandbox` 又会不必要地关闭 renderer sandbox。

### 三路并行

- 0.6.24 正式日志显示任务 2 在 16:45:36 和 16:46:22 两次进入 `submission-attempt`，任务 3 在 16:47:52 和 16:48:39 两次进入提交。
- 任务 2 于 16:47:08 已报告“发送按钮已点击，但没有确认接收”，之后任务 4、5 和任务 2 的自动重试仍继续提交；16:51:36 再次收到 `conversation-access-rate-limit`。
- 因而直接原因不是三路结果等待本身，而是“不确定发送后的自动补点 + 批次重试 + 后续任务继续分配”叠加。

## 解决方式

### Windows 启动兼容

- electron-builder 设置 `asar: false`，安装后的应用代码位于 `resources/app`。
- Windows 主进程在 ready 前添加 `disable-gpu-sandbox`；没有使用 `no-sandbox`，主 renderer 继续保持 `sandbox: true`、`contextIsolation: true` 和 `nodeIntegration: false`。
- 新增打包应用专项，直接启动 `release/win-unpacked/耀创工坊.exe` 并断言版本、目录结构、GPU 开关与 renderer 沙箱边界。

### 新图标

- 使用 Hale 提供的 1536x1536 PNG 生成 16、24、32、48、64、128、256 像素多分辨率 ICO。
- 同步替换 `build/icon.ico`、安装器/EXE 图标、额外资源图标、renderer favicon、托盘图标和工作台左上角图标。

### 三路并行保护

- ChatGPT 提交最小间隔由 30 秒提高到 60 秒，额外标签页建立间隔由 10 秒提高到 30 秒。
- 删除做图、原图分析和网感姿势分析中“发送未确认后自动再点一次”的逻辑。
- 已点击发送但没有可靠结果时，设置五分钟提交保护并停止分配新任务；其他已经确认发送的通道仍可继续等待和保存。
- 该任务保留在断点中，后续由用户查看 ChatGPT 页面并等待保护期结束后再继续，避免同一批次重复提交。

## 经验教训

- “点击后没有页面确认”不是自动补点的充分条件；网页状态可能滞后，重复点击的账号风险高于当前任务失败。
- 三路并行应并行等待生成，不应并行轰击提交入口；任何不确定提交都必须先冻结新请求并保留断点。
- Windows 兼容故障要验证最终安装结构和打包 EXE，源码 Electron 能启动不能证明 ASAR 安装包在其他机器上可用。
- 图标更新必须同时覆盖安装器、主程序、快捷方式、托盘和 renderer，不能只替换一张界面图片。
