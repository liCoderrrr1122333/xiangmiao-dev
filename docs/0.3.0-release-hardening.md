# 耀创工坊 0.3.0 发布加固记录

## 发布范围

- 基线：0.2.4（`73f396b`）
- 分支：`feature/0.3.0-prompt-model-parallel-upgrade`
- 目标：提示词草稿与发送快照、动态模型选择、1/2/3 路并行、恢复与自动保存、一键升级安装器。
- 保持不变：原图像素尺寸、红圈外保护、一键蒙脸、人脸与衣物参考图、AI 分析回填、结果归档、批量断点续做和专属 Chrome 登录资料。

## Graphify 调用链结论

关键链路为：

1. `App.tsx` / `projectStore.ts` 管理当前可编辑草稿、恢复状态和开始做图入口。
2. `promptDraftPolicy.ts` 在点击开始做图时生成不可变发送快照。
3. `preload/index.ts` 通过 IPC 把同一快照、模型选择和并行度交给主进程。
4. `main/index.ts` 在附件上传前确认模型，然后把任务分配给独立标签页。
5. `chromeChatGpt.ts` 保持一个持久 BrowserContext，并提供管道主通道、固定端口后备和窗口恢复。
6. `chatGptParallelPolicy.ts` 管理任务编号、延迟重试、全局停止和精确检查点。
7. `installer.nsh` 只根据固定产品身份升级，保留 D 盘业务数据和专属 Chrome 资料。

## 问题记录

### 1. 修改提示词后仍发送旧正文

- 现象：生成提示词后手动修改，开始做图仍读取旧 `promptHistory`。
- 根因：生成动作过早写入历史，发送动作又从历史读取；React 状态更新存在时序差。
- 解决：生成只产生可编辑草稿；开始做图时读取编辑框当前正文，创建不可变发送快照，再统一写入历史、发送记录、IPC、导出和归档。
- 经验：发送事实必须在用户确认动作处一次性冻结，不能从多个可变状态源重新拼装。

### 2. 重启后“一键生成提示词”无法使用

- 现象：慢速恢复或自动保存异常后，按钮保持阻断或旧项目被空状态覆盖。
- 根因：项目读取与自动保存并行，未区分“尚未恢复”和“已恢复为空项目”。
- 解决：增加 hydration 状态；恢复完成前禁止自动保存；采用临时文件成功写入后原子替换并保留备份；恢复后重新校验原图、红圈和参考图，显示可操作的阻断原因。
- 经验：持久状态必须有明确初始化边界，空状态不能默认代表用户主动清空。

### 3. 模型选择器误显示“打开个人资料菜单”

- 现象：真实 Plus 账号页面被显示为“跟随当前 · 打开‘个人资料’菜单”。
- 根因：旧规则用 `/pro/` 模糊匹配，`profile` 和账户套餐文字被误判为模型入口。
- 解决：模型入口必须具有 `model-switcher/model-selector/model-picker` 结构标识，或明确“选择模型/当前模型”语义；账户、头像、侧栏和通用菜单全部排除；当前网页无模型选择器时只显示“跟随当前模型”。
- 经验：网页自动化不能依赖短字符串包含关系，必须同时使用结构、角色、位置和负向证据。

### 4. 并行重试被其他通道提前领取

- 现象：某通道进入退避后，空闲通道可能立即领取同一失败任务。
- 根因：队列只记录任务索引，没有把“最早可重试时间”作为可调度条件。
- 解决：延迟任务携带 `readyAt`；所有通道统一经过可领取判断；活动 worker 数包含进行中的任务；每个标签页持有独立任务、附件、回复基线和结果状态。
- 经验：并发调度的重试时间是任务状态的一部分，不能只在 worker 内部 `sleep`。

### 5. 旧安装版本可能形成第二个副本

- 现象：历史版本可能位于不同注册表视图或自定义目录，普通覆盖安装不足以证明不会产生双份安装。
- 根因：安装身份和旧版清理缺少显式、可验证的失败边界。
- 解决：固定历史 GUID；同时检查 HKCU/HKLM 与 32/64 位视图；联合校验产品名、发布者、卸载程序、主程序和安装目录；旧版卸载失败立即停止；卸载始终传入保留数据参数。
- 经验：升级清理只能依据精确身份，不能扫描磁盘或模糊删除目录。

### 6. 自定义目录升级验证一度误报失败

- 现象：安装启动器返回后固定等待 18 秒，短暂读不到新卸载记录。
- 根因：NSIS 外层启动器先退出，安装子进程仍在完成注册表和快捷方式写入。
- 解决：验证脚本改为等待版本、主程序、卸载记录和快捷方式同时达到稳定状态，而不是固定等待秒数。
- 经验：安装成功条件应以系统最终状态为准，不能以外层进程退出或单一计时器为准。

## Hallmark UI 审计

- 保留深色高级工作台和紫色品牌强调色，没有引入动画依赖。
- 新增模型和并行控件采用现有设计令牌，覆盖默认、悬停、焦点、按下、禁用、加载、错误和成功状态。
- 并行度使用紧凑的 1/2/3 分段控件；状态动效仅用于上传、分析、生成和完成。
- 1280×720 无横向溢出；支持 `prefers-reduced-motion`。
- Hallmark 预交付评分：P5 / H5 / E5 / S5 / R5 / V4。

## 验证结果

- `npm test`：80/80 通过。
- `npm run verify:chrome`：管道主通道、固定端口后备、端口冲突回退、多标签隔离、关闭子标签不影响根标签、隐藏/显示和屏幕外窗口恢复全部通过。
- 真实 Plus 账号：当前页面没有模型切换器时正确显示“跟随当前模型”；没有再把个人资料菜单作为模型。
- 最终安装版：首次启动、恢复登录、检查登录、查看窗口、1280×720、提示词模式和 1/2/3 路控件通过。
- 升级矩阵：0.1.1、0.2.1、0.2.4 均实际升级到 0.3.0；0.2.1 覆盖旧版运行中升级；0.2.4 覆盖自定义安装目录。
- 三轮升级均保留业务数据和专属 Chrome 资料，验证文件 SHA-256 前后完全一致。
- 未执行真实批量图片生成，以免消耗用户 ChatGPT 额度；发送、失败识别、乱序保存、暂停和断点恢复由单元测试与专项浏览器测试覆盖。

## 回滚与残余风险

- 回滚基线：`baseline/0.2.4-stable` / `73f396b`。
- 0.3.0 独立功能提交可逐项回滚，不需要重置工作树。
- ChatGPT 网页 DOM 仍可能由服务端更新；当前策略采用结构证据、负向排除、超时、诊断日志和失败停止，不会静默切换模型。
- Google OAuth、验证码和人机验证仍由用户手动完成，自动化不会点击这些安全步骤。
