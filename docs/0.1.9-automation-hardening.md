# 耀创工坊 0.1.9 自动化加固记录

## 问题现象

- 同一份已登录的专属 Chrome 会话，软件可能先显示“已登录”，随后又显示“需要重新登录”。
- 全新安装首次启动时，登录检查可能长时间停留在检查中，最后误报页面空白或检查超时。
- 点击“查看窗口”可能关闭并重启专属 Chrome，增加页面丢失、窗口失效和登录检测竞态。
- ChatGPT 首次登录页的侧栏登录入口偶发无响应，Cookie 弹层还可能遮挡登录选项。

## 根因

1. 旧登录探针把 ChatGPT 页面加载期间短暂出现的登录控件直接判定为退出登录，没有以 `/api/auth/session` 的认证结果为最高优先级。
2. 渲染进程可能复用旧的异步检查请求，后返回的旧结果会覆盖当前后端或当前页面的真实状态。
3. 后台 Chrome 使用最小化窗口状态。新版 Chrome 会降低最小化页面的渲染和脚本调度优先级，导致 CDP 页面探针超时。
4. 后台模式切换到可见模式时会释放并重建 Chrome，登录页加载、窗口状态和探针因此发生竞态。
5. 自动进入登录流程时选中了页面中第一个“登录”按钮；侧栏按钮可靠性低于顶部带 `data-testid="login-button"` 的主入口。
6. 首次启动的 Chrome、页面恢复和三次退出确认总耗时可能超过原来的 40 秒界面等待上限。

## 解决方式

- 登录探针增加 `/api/auth/session` 校验。已认证会话优先于页面中短暂出现的登录控件。
- 退出登录必须连续取得 3 次明确证据；已确认登录后保留 5 分钟保护期，页面短暂重载不会改写为退出。
- 登录检查按“浏览器后端 + URL”隔离请求，并以递增序号丢弃迟到的旧结果。
- 专属 Chrome 改为单一常驻进程。后台仅通过 Win32 隐藏窗口，不再设置浏览器最小化状态。
- “查看窗口”、登录后转后台和自动化运行复用同一个 Chrome PID 与调试端口，不再因前后台切换重启。
- 登录窗口使用顶部主登录入口并通过 CDP 发送可信鼠标事件；首次进入时自动拒绝非必需 Cookie，再打开登录面板。
- 增加登录状态后台监听，用户完成登录后自动更新软件状态并隐藏同一个 Chrome 窗口。
- 首次冷启动的界面等待上限提高到 100 秒，8 秒后显示明确的专属 Chrome 启动/恢复进度。
- 新项目和新安装默认使用专属 Chrome，并将“区域编辑定制版”设为 Image 2.0 提示词默认模式。

## 验证结果

- 真实已登录 Plus 会话启动后识别为已登录。
- 连续点击“检查登录”5 次，5 次均保持已登录，单次复查约 0.4-0.6 秒。
- 注入可见的临时 `Sign in` 控件时，认证会话仍保持已登录。
- 全新独立用户目录首次启动后正确显示“需要完成登录”，未再误报已登录。
- 点击“查看窗口”后自动清除 Cookie 遮挡并显示“登录或注册”面板。
- Google 登录入口进入真实 `accounts.google.com` 页面。
- 窗口显示、检查登录和再次隐藏前后，Chrome PID 与调试端口保持不变。
- 后台状态的专属 Chrome 顶层可见窗口数量为 0；查看时为 1；检查完成后恢复为 0。
- 新项目默认提示词模式为“区域编辑定制版”。
- 1280×720 最低正式支持分辨率下，页面无横向溢出，顶部工具栏不再出现滚动条。
- `npm test`：47 项测试全部通过。

## 经验教训

- 登录状态必须由认证接口、账号信号和编辑器状态共同判断，不能依赖某个短暂 DOM 文本。
- 隐藏自动化浏览器和最小化浏览器不是同一件事；最小化可能让页面脚本失去及时调度。
- 前后台切换应改变窗口可见性，不应改变浏览器进程所有权或重建用户会话。
- 登录页属于外部持续变化界面，入口选择、Cookie 弹层和 OAuth 跳转都需要可恢复的多阶段检测。
