# 耀创工坊 0.6.21 提示词状态一致性修复

日期：2026-08-14

## 问题现象

- 删除穿搭参考图、清空网感姿势、修改当前分支实际使用的原图理解或切换人脸主参考图后，旧的区域提示词仍可能保持可发送状态。
- 替换主图后，旧主图分析、自定义保护项和提示词草稿仍可能残留。
- 重启项目时，已用于发送的提示词快照可能被恢复成当前可编辑草稿。
- 更换主图后，上一张图尚未返回的 AI 分析或网感姿势请求可能迟到并覆盖新项目状态。

## 根因

1. 区域提示词新鲜度只比较非空素材签名；当前素材被删除后，对应校验项也随之消失。
2. 提示词校验没有比较当前草稿与当前四分支规则实时重建的结果，因此部分有效分析字段变化不会触发失效。
3. `setMainImage` 只清理了圈选、蒙脸和姿势选择，没有清理所有由旧主图派生的分析与草稿状态。
4. 项目恢复只处理历史列表，未完整排除显式已发送草稿及与已发送历史同 ID 的污染草稿。
5. AI 分析和网感姿势回填没有确认请求发起时的主图仍是当前主图。

## 解决方式

- 区域模式始终校验穿搭与姿势签名；素材删除或姿势清空同样会让旧提示词失效。
- 使用现有 `regionalPrompt(project)` 重建当前分支提示词并进行精确新鲜度比较；只关注当前分支真正使用的素材字段，自定义模式保持原行为。
- 替换主图时清理旧分析、自定义保护项、当前草稿和网感姿势派生状态，同时保留人脸/穿搭参考图、发送历史、提示词历史、结果归档和项目兼容数据。
- 恢复项目时拒绝显式已发送草稿和与已发送历史同 ID 的草稿；未带已发送标记的旧项目历史继续兼容。
- AI 分析和网感姿势使用请求主图 ID 原子回填；主图已变化时丢弃迟到结果并显示提示。

## 经验教训

- 提示词新鲜度不能只依赖“当前非空素材”的签名；删除素材也是需要失效旧草稿的状态变化。
- 主图是分析与草稿的所有权边界。替换主图必须同步清理派生状态，并用主图 ID 隔离异步回填。
- 提示词历史、当前草稿和已发送快照职责不同，项目恢复时必须保留历史但不能复活已发送内容。
- 发布必须从安装器、解包应用和运行时三处核对版本；历史安装包哈希不能证明新构建。
