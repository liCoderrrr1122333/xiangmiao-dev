# 1.1.1 耀创工坊图标识别度升级

日期：2026-08-16

## 问题现象

- 0.6.25 图标把整块黑色背景一起打入图标，Windows 桌面上会看到明显黑底。
- 去掉黑底后的第一版主体留白较多，缩成桌面图标后吉祥物偏小，眼睛和微笑不够醒目。
- 外置方形金框与吉祥物本身脱节，不符合 Hale 希望的圆润主体和贴身金色轮廓。

## 真实根因

- 旧图标源文件是无 alpha 的 RGB PNG，黑色场景背景不是 Windows 生成，而是源图像素的一部分。
- 桌面图标需要同时兼顾 16 至 256 像素；只按大图观感设计，会让主体和表情在小尺寸下失去辨识度。
- 透明底、白色底板和吉祥物轮廓是三个独立层级，早期范例没有明确分离这三个层级。

## 解决方式

- 使用确认后的紫黑镜头吉祥物：缩短腿部、放大头部面板、眼睛和微笑，主体约占白色底板的 94%，头顶、双拳和双脚均完整保留，并留有窄幅安全间距。
- 香槟金轮廓直接贴合吉祥物身体、手臂和鞋子的外沿，不再使用脱离主体的装饰方框。
- 直接读取桌面 `QQ.lnk` 指向的 `D:\qq\QQ.exe` 图标，只复用其白色大圆角底板 alpha 轮廓：256 像素下两者均覆盖 `0,0-255,255`，顶边和左边可见区间均为 `46-209`；不复制企鹅、围巾或其他品牌内容。
- 从同一透明主图生成 16、24、32、48、64、128、256 七档 Windows ICO，并同步应用、安装器、快捷方式、托盘、favicon 和工作台图标。
- 正式版本按 Hale 指定从 0.6.25 升级为 1.1.1，安装身份、目录和用户数据兼容策略保持不变。

## 经验教训

- Windows 图标是否有黑底必须检查源文件 alpha，不能只在深色预览器里凭视觉判断。
- 图标验收必须同时看大图和 32/48 像素缩略图；桌面可读性主要取决于主体占比和表情对比。
- “参考某应用图标”应拆成结构参考与品牌内容参考，只采用白色大圆角底板结构，不复制企鹅、配色或快捷方式箭头。
- 二进制资源更新应固定透明通道、尺寸阶梯和资源链测试，避免后续构建悄悄退回旧图。
